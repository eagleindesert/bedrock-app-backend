## 1.2 문제 정의

1. **정보가 흩어진다.** 학교 시간표, 팀 프로젝트, 아르바이트처럼 성격이 다른 일정이 메신저 · 메모장 · 기본 캘린더에 나뉘어 있으면 같은 내용을 여러 번 적어야 하고, 관련된 정보가 이어지지 않아 빠뜨린다.
2. **시작이 무겁거나 답답하다.** 표와 구조를 먼저 짜야 하는 도구는 시작할 시간이 없고, 쓰는 방식이 정해진 도구는 내 방식과 맞지 않는다.
3. **계획은 자주 틀어진다.** 못 한 할 일을 어디로 옮길지 매번 직접 찾아야 해서 밀린 일이 쌓이면 계획 자체를 놓는다.

## 1.3 포지셔닝

베드락은 일정 · 할 일 · 노트를 따로 만드는 앱이 아니라 **아이템 하나에 필요한 성격을 붙여 여러 자리에서 함께 보는 앱**이다.

1. **한 번 적고 여러 자리에서 본다.** 팀플 회의 하나를 적으면 캘린더의 그날에 서고, 할 일 상태를 붙이면 끝냈는지 체크하고, 본문을 붙이면 회의록이 된다. 메신저 · 메모장 · 캘린더에 같은 내용을 세 번 적지 않고, 복사본도 생기지 않는다.
2. **적으면 정리되고, 지금 화면에서 확인한다.** 홈과 모든 모듈 아래의 AI 입력 바에 문장을 적으면 앱이 아이템을 만들거나 고치거나 지우고, 일정을 물으면 받아 둔 아이템에서 찾아 답한다. 검증을 마친 결과는 바로 저장해 지금 보는 화면에 반영하고 바뀐 자리를 강조한다. 결과마다 되돌리기와 직접 고치기가 있다. 대상이나 범위가 분명하지 않을 때만 그 부분을 묻는다. AI를 쓰지 않아도 직접 입력으로 모든 기본 기능을 쓴다.
3. **틀어진 계획은 앱이 제안하고 사용자가 고른다.** 재조정 제안은 사용자가 받아들이기 전에는 반영하지 않는다. 사용자가 명시적으로 요청한 AI 수정은 F-43 「문장 AI 해석」을 따른다.

**설계와 시장은 따로 본다.** 기능과 데이터 구조는 "계획하는 누구나"에 맞추고, 특정 사용자군에만 뜻이 있는 말은 화면 표시에서만 쓴다. 첫 시장인 대학생은 시간표 불러오기로 들어오지만, 이 기능은 코어 위에 얹는 **애드온**이고 코어는 그것 없이 완결된다. 학생용으로만 설계하면 졸업하는 순간 쓸 이유가 사라지기 때문이다.

# 2. 기본 원칙

## 2.1 판단이 갈릴 때

위에서 아래로 적용한다.

1. **사용자가 쓴 것을 앱이 덮지 않는다.** 자동 처리가 사용자 입력을 조용히 지우지 않는다. 덮어야 하면 먼저 알린다.
2. **시작을 막지 않는다.** 설정이나 학습을 요구하는 기능을 첫 화면에 두지 않고, 미리 만든 기본값으로 바로 쓰게 한다.
3. **일관된 것은 규칙이지 결과가 아니다.** 규칙이 같으면 자리마다 겉모습이 달라도 된다.

**플랫폼이 갈리면 그 플랫폼의 관례가 먼저다.** iPhone은 Apple의 HIG와 기본 컴포넌트의 동작을 웹과 같은 동작보다 먼저 따른다. 그 차이는 각 기능과 4.1의 표에 적는다.

## 2.2 데이터 원칙

1. **아이템에는 종류가 없다.** 상태가 있으면 할 일, 본문이 있으면 노트라는 식으로 가진 속성으로 판정하고 성격은 저장하지 않는다.
2. **서버가 정답이다.** iOS 앱의 기기에는 사본과 아직 보내지 않은 쓰기만 있고, 웹은 사용자 데이터를 기기에 남기지 않는다.
3. **같은 칸이 부딪치면 사용자가 고른다.** 서버 값으로 조용히 덮지 않는다.
4. **지워도 연결 기록은 남긴다.** 삭제는 휴지통으로 가는 소프트 삭제이고, 30일 뒤 물리 삭제할 때만 연결 기록도 지운다.
5. **반복은 규칙이 정본이다.** 회차는 볼 때 계산하고, 사용자가 손댄 회차의 손댄 칸만 저장한다.
6. **확장은 코드 배포 없이 한다.** 아이템 속성과 입력 화면 구성은 서버 DB의 데이터로 늘린다.

## 2.3 범위 원칙

1. **설계는 누구나에 맞춘다.** 특정 사용자군의 말을 데이터 구조 · 필드 이름 · 기능 이름에 넣지 않는다.
2. **검증 전에 과투자하지 않는다.** 나중에 붙일 수 있게만 설계한다.
3. **세부는 구현 중에 정한다.** 이 문서는 골격과 구현이 갈리는 규칙까지만 정한다.

## 3.1 계정과 로그인

### F-01. 이메일 가입

이메일과 이름만 받아 가입을 시작한다. 그 주소로 보낸 숫자 코드를 가입을 시작한 화면에 넣고 같은 화면에서 비밀번호를 정해야 계정이 선다. 메일 속 링크로 끝내는 길은 없고, 인증 전의 가입은 계정이 아니라서 로그인할 수 없다.

**동작 흐름**

1. 사용자가 이메일과 이름을 낸다.
2. 서버가 가입을 받아 두고 바로 응답한 뒤 코드 메일을 뒤에서 보낸다.
3. 사용자가 같은 화면에 코드를 넣고 비밀번호를 정한다.
4. 서버가 코드를 먼저 확인하고, 맞을 때만 비밀번호 규칙을 검사하고 해시를 건다. 계정이 서고 세션이 발급된다.

**규칙**

- 인증 전에 같은 이메일로 다시 가입하면 앞선 가입과 코드를 버린다. 코드가 만료되거나 시도 한도에 닿으면 그 가입을 지우고 처음부터 다시 가입한다.
- 이미 인증을 마친 계정이 있는 이메일로 가입해도 화면과 응답은 처음 가입과 같다. 서버는 코드 대신 "이미 가입된 주소이니 로그인하거나 비밀번호를 재설정하라"는 메일을 보내고, 그 화면에 넣는 코드는 모두 틀린 코드로 받는다. 탈퇴 유예 중인 계정의 이메일이면 코드를 보내 F-06대로 고르게 한다.
- 인증 전에 같은 이메일로 구글이나 Apple 로그인을 하면 이 가입을 버리고 그 계정으로 선다. 그 로그인에 메일 코드가 필요하면(F-02) 가입을 버리는 것은 코드를 확인한 뒤다.

### F-02. 로그인과 로그인 유지

이메일과 비밀번호, 구글, Apple 세 방식이 iOS 앱과 웹에 모두 있다.

**동작 흐름**

1. 사용자가 이메일과 비밀번호를 내거나, 구글 · Apple의 인가를 마친다.
2. 서버가 자격을 확인하고 세션을 발급한다. 이메일 계정은 인증을 마친 것만 들어온다.
3. 앱이 워크스페이스를 통째로 받는다. iOS 앱은 기기에 사본으로 두고(사본이 있으면 먼저 그린다), 웹은 탭 메모리에만 둔다.
4. 들어온 길에 따라 연다.

   | 들어온 길                | 여는 곳                                                                                                                |
   | ------------------------ | ---------------------------------------------------------------------------------------------------------------------- |
   | 앱 아이콘으로 새로 실행  | 홈                                                                                                                     |
   | 주소(웹)                 | 그 주소의 모듈이나 아이템. 홈을 거치지 않는다                                                                          |
   | 위젯 · 기기 알림(iPhone) | 특정 화면 진입을 지원하면 해당 모듈이나 아이템을 열고, 지원하지 않으면 홈을 연다. MVP 범위는 F-36 「위젯 둘」을 따른다 |
   | 백그라운드에서 돌아옴    | 보던 화면 그대로. 홈으로 옮기지 않는다                                                                                 |
   | 세션이 끝나 다시 로그인  | 원래 보던 화면(이 절의 규칙과 같다)                                                                                    |

5. 처음 들어온 사용자에게는 따로 온보딩 안내를 띄우지 않는다. AI 입력 바를 누르면 빈 대화 영역의 예시 문장(F-08)이 적는 법을 보여 준다. AI 해석 동의(F-43)는 처음 보낼 때 받는다.

**규칙**

- **로그인 유지:** iOS 앱은 늘 유지한다. 웹은 30분 동안 활동이 없으면 끝나고(사용자 입력이 만든 요청만 활동으로 친다), 로그인할 때 유지를 고르면 유지한다. 유지된 로그인은 30일 동안 쓰지 않으면 끝난다.
- **같은 이메일의 계정은 하나로 잇는다.** 소유가 확인된 이메일끼리만 잇고, 이메일은 소문자로 맞춰 견준다.
- **구글 · Apple 첫 로그인**은 제공자가 그 이메일을 확인했고 그 주소의 주인일 때만 추가 확인 없이 끝난다. 구글은 gmail.com이거나 Google Workspace 계정(ID 토큰에 hd가 있을 때), Apple은 icloud.com · me.com · mac.com이거나 비공개 릴레이 주소다. 그 밖은 그 주소로 보낸 코드를 로그인을 시작한 화면에 넣어야 끝난다. 한 번 이은 뒤로는 제공자의 계정 id로 찾는다.
- **비밀번호 연속 실패:** 같은 주소로 10회 연속 틀리면 잠깐 막고(처음 1분 안팎, 거듭되면 늘린다), 100회면 재설정하거나 계정이 서야 풀린다. 막힌 동안의 응답은 틀린 비밀번호와 같고, 재설정은 막히지 않는다.
- 세션이 끝나 다시 로그인하면 원래 보던 화면으로 돌아간다. 웹은 아이디 저장을 고르면 마지막 이메일을 채운다.

**아직 정하지 않았다:** 이메일을 가린 Apple 계정(이메일이 릴레이 주소다)을 다른 방식으로 들어온 같은 사람의 계정과 잇는 방법. 앱 스토어 제출 전에 정한다.

### F-03. 비밀번호 재설정

**동작 흐름**

1. 사용자가 로그인 화면에서 재설정을 고르고 이메일을 낸다.
2. 앱이 코드 칸을 연다. 계정이 있든 없든 같은 안내다.
3. 계정이 있으면 서버가 코드를 보낸다. 사용자가 재설정을 시작한 화면에 코드를 넣고 새 비밀번호를 정한다.
4. 서버가 코드를 먼저 확인하고 비밀번호를 바꾼다. 유지된 로그인을 포함해 그 계정의 모든 기기 로그인을 끝내고 새 세션은 주지 않는다. 계정 이메일로 알린다.
5. 사용자가 새 비밀번호로 로그인한다.

**규칙:** 구글이나 Apple로만 쓰던 계정도 이 흐름으로 비밀번호를 만든다. 로그인이 끝난 기기는 사본을 지우고 보내지 않은 쓰기는 봉해 둔다. 봉한 쓰기는 화면에 그리지도 보내지도 않다가, 같은 계정이 새 비밀번호로 다시 로그인하면 보낸다. 다른 계정이 로그인하거나 30일 안에 돌아오지 않으면 지운다(F-44의 다른 계정 로그인과 같다). 잃어버린 기기를 비우는 일은 기기 끊기(F-05)와 "내가 아니다"가 맡는다. 탈퇴 유예 중인 계정이면 코드를 넣은 화면에서 되살릴지 고르고, 되살리지 않으면 아무것도 바뀌지 않는다.

### F-04. 메일 코드

가입 · 비밀번호 재설정 · 탈퇴 유예 계정의 되살리기와 새로 시작하기 · 구글과 Apple의 첫 로그인이 같은 규칙을 쓴다.

| 항목        | 규칙                                                                               |
| ----------- | ---------------------------------------------------------------------------------- |
| 형식        | 서버가 암호학적 난수로 뽑은 숫자 6자리                                             |
| 묶임        | 그 일을 시작한 세션과 그 일에 묶는다. 한 번만 쓴다                                 |
| 수명        | 보낸 지 10분. 세션을 써도 늘지 않는다                                              |
| 틀림        | 한 코드에 다섯 번 틀리면 끝난다                                                    |
| 다시 받기   | 앞선 코드를 보낸 지 60초 뒤부터. 다시 받으면 앞선 코드는 끝난다                    |
| 주소당 발송 | 1시간에 5통, 24시간에 20통. 요청자(IP · 세션)마다의 한도도 두고 값은 구현이 정한다 |
| 연속 실패   | 주소마다 100회 연속 틀리면 24시간 동안 그 주소로 코드를 보내지도 받지도 않는다     |
| 저장        | 코드 저장소 밖의 키로 만든 HMAC으로만 둔다                                         |

**규칙**

- 세션마다 기다리는 일은 하나다. 새 일을 시작하면 앞선 일과 코드가 끝난다. 가입 · 첫 로그인 · 재설정의 코드는 그 일이 닿은 탈퇴 유예 계정의 확인을 갈음한다.
- 코드 메일에는 무슨 일의 코드인지, 요청한 때, 플랫폼을 적고 위치와 링크는 싣지 않는다. 인증 전에 가는 메일에는 상대가 적은 이름을 싣지 않는다.
- 서버는 요청에 먼저 응답하고 메일은 뒤에서 보내며 실패하면 다시 보낸다. 반송된 주소에는 다시 보내지 않는다.

### F-05. 로그아웃 · 기기 목록 · 계정 알림 메일

**로그아웃:** 계정 메뉴에서 한다. 보내지 않은 쓰기가 있으면 먼저 보내고, 보낼 수 없는 쓰기나 내려 둔 입력 화면(F-10)이 남으면 그 수를 알려 버리고 나갈지 취소할지 고르게 한다.

**기기 목록:** 설정의 계정 세부에서 로그인한 기기마다 플랫폼 · 모델 · 마지막으로 쓴 때 · 지금 기기인지를 본다. 모델은 기기가 보낸 값이라 글자로만 그린다. 고른 기기 하나나 지금 기기를 뺀 모든 기기를 로그아웃한다. 끊긴 기기는 다음 요청에서 그 사실을 받아 사본과 보내지 않은 쓰기를 묻지 않고 지운다. 잃어버린 기기를 끊으려는 기능이라 남기지 않는다.

**계정 알림 메일:** 처음 보는 기기의 로그인, 새 제공자(구글 · Apple) 연결, 비밀번호 재설정 때 계정 이메일로 알린다.

- 처음 보는 기기는 기기가 간직한 id(iOS는 이 기기에서만 읽히는 Keychain, 웹은 HttpOnly · Secure 쿠키)로 가린다. 메일을 줄이는 데만 쓰고 권한 판정에는 쓰지 않는다.
- 메일에는 시각과 플랫폼을 싣고 위치는 싣지 않는다.
- 새 제공자 메일의 "내가 아니다" 링크는 확인 화면만 연다. 그 화면에서 끊기를 골라야 제공자를 끊고 모든 기기를 로그아웃한다. 메일 보안 검사기가 링크를 먼저 열어도 아무 일이 없어야 해서다. 링크는 로그인 없이 열리고 한 번 쓰면, 또는 7일 뒤 끝난다.

### F-06. 탈퇴

설정의 계정 세부에서 탈퇴한다(앱 스토어 심사 요건). 확인 창에서 30일 뒤 지워진다는 것을 알린다. 탈퇴하면 모든 기기의 로그인이 끝나고 계정이 소프트 삭제되며, Apple 계정이면 Apple 토큰을 해지한다. 30일 뒤 서버가 그 계정의 데이터, 그 계정만 속한 컬렉션, 데이터 키를 물리 삭제한다.

**규칙:** 30일 안에 그 이메일로 로그인하거나 가입하면 옛 계정을 되살릴지 새로 시작할지 고른다. 고르기 전에 반드시 메일 코드를 넣는다. 비밀번호가 맞아도, 제공자가 주인이어도 받는다. 되돌릴 수 없는 결정이라서다. 새로 시작하면 옛 계정을 곧바로 물리 삭제한다.

## 3.2 앱 구조

### F-07. 홈과 모듈

앱의 시작은 **홈**이고, 아이템은 **모듈**(캘린더 · 시간표 · 할 일 · 노트 · 모아보기)에서 본다. 하단 탭 바와 앱 안 대시보드는 없다. 홈과 모든 모듈 아래에는 AI 입력 바(F-08)가 있다. AI 입력 바는 화면을 오가는 탭 바가 아니고, 모듈을 오가는 일은 모듈 패널이 맡는다.

| 자리          | 무엇을 보여 주나                                                                                                                                                         |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 홈            | 오늘 날짜와 요약(일정 몇 · 할 일 몇, 일정에는 시간표 회차도 센다), 다음 일, 오늘 이어지는 일정과 할 일. 그 아래 밀린 할 일 · 이번 주 마감 · 고정 목록 · 정리 대기의 요약 |
| 캘린더 모듈   | 모든 아이템을 날짜 위에 세운다. 월력과 일 상세                                                                                                                           |
| 시간표 모듈   | 켜진 컬렉션의 시간표 아이템을 고른 주의 실제 회차로 그린다(F-32). 시간표 아이템의 입구다                                                                                 |
| 할 일 모듈    | 할 일을 모아 처리한다. 오늘 할 일이 먼저 선다(F-51)                                                                                                                      |
| 노트 모듈     | 노트를 모아 읽고 쓴다(F-52)                                                                                                                                              |
| 모아보기 모듈 | 컬렉션과 그 안의 아이템을 파일 탐색기처럼 본다(F-37)                                                                                                                     |

**홈에서 하는 일 (수정 가능성 높음)**

홈은 문장을 적지 않는 날에도 오늘을 확인하고 처리하는 화면이다. 오늘 할 일이 가운데이고, 나머지는 요약해 접을 수 있게 둔다. AI 입력 바는 아래 한 줄을 차지하고 위 내용을 밀어내지 않는다.

| 순서 | 묶음         | 보여 주는 것                                                                                      | 보이는 때                          |
| ---- | ------------ | ------------------------------------------------------------------------------------------------- | ---------------------------------- |
| 1    | 다음 일      | 다음 일정이나 할 일을 크게(때 · 남은 시간 · 이름)                                                 | 오늘 남은 일이 있을 때             |
| 2    | 오늘         | 오늘 이어지는 일정과 할 일을 줄마다 짧게. 할 일 줄은 그 자리에서 체크한다(F-17)                   | 늘                                 |
| 3    | 밀린 할 일   | 틀어진 할 일(F-19)과 제안 시간. 제안 시간을 누르면 옮기고, "다른 시간 고르기"는 재조정 창을 연다  | 있을 때. 요약하고 접을 수 있다     |
| 4    | 이번 주 마감 | 마감이 이번 주인 미완료 할 일. 완료한 것은 빠진다. 오늘 묶음에 이미 선 할 일은 다시 세우지 않는다 | 있을 때. 요약하고 접을 수 있다     |
| 5    | 고정 목록    | 고정한 아이템(F-26)                                                                               | 고정한 것이 있을 때. 많으면 접는다 |
| 6    | 정리 대기    | 처리하지 못한 문장(F-49)과 다시 시도                                                              | 처리할 문장이 있을 때              |

- 줄을 누르면 그 일이 서는 모듈에서 상세를 연다. 시간표 아이템의 회차는 시간표, 할 일은 할 일, 나머지는 캘린더이고, 줄에 그 모듈을 꼬리표로 보인다.
- 묶음의 정확한 배치와 접힌 모양은 Figma가 정한다.

**모듈 오가기 동작 흐름**

1. 왼쪽 위 단추를 누르면 모듈 패널이 열린다. 맨 위가 홈이고 그 아래 모듈마다 칸이 하나다. 칸은 아이콘과 이름을 함께 보인다.
2. 칸을 누르면 홈이나 그 모듈로 바로 간다.
3. 오른쪽 위 단추를 누르면 대화 기록과 설정 패널이 열린다(F-50). 패널에서 알림 목록(F-41)과 설정으로 간다. 새 알림이나 풀지 않은 충돌이 있으면 이 단추에 표시하고, 모양은 Figma가 정한다.
4. 바깥을 누르거나 같은 단추를 다시 누르면 패널이 닫힌다.

**규칙**

- **패널은 단추로만 연다.** 화면 가장자리 밀기는 iOS의 뒤로 가기와 겹쳐서 쓰지 않는다.
- **모듈 패널에는 홈과 모듈 다섯이 모두 선다.** 모듈을 숨기거나 더하는 기능이 MVP에 없으므로 모듈 더하기 칸을 두지 않는다. 사용자 정의 모듈은 MVP 밖이다(6장).
- **마지막으로 본 모듈을 기억하지 않는다.** 일반 새 실행은 홈을 열고, 직접 주소 진입과 백그라운드 복귀는 F-02 「로그인과 로그인 유지」를 따른다.
- **작업은 그 자리에서 이어 간다.** AI 요청을 마쳐도, 직접 입력을 저장해도 지금 모듈에 남는다. 홈으로 옮기지 않는다.
- 웹에서 홈과 각 모듈, 아이템 상세는 주소로 바로 열린다. 주소와 탭 제목에 사용자가 적은 글을 싣지 않는다.

**아직 정하지 않았다:** 아이템이 하나도 없는 첫 실행의 홈 모양. 웹의 모듈 오가기 모양.

### F-08. AI 입력 바

홈과 모든 모듈 아래에 늘 있는 전역 입력이다. 누르면 지금 화면 위에서 바로 대화한다. 캘린더의 빈 칸처럼 맥락을 미리 채우는 직접 입력 길은 따로 남는다.

**동작 흐름**

1. 평소에는 화면 아래에 한 줄 높이의 긴 입력 바가 있다.
2. 입력 바를 누르면 입력 영역과 키보드가 열리고 뒤의 모듈은 계속 보인다. 선택 맥락이 있으면 입력 바 위에 보인다.
3. 사용자가 문장을 적고 보낸다. 대화 영역에 처리 상태가 보인다.
4. AI가 해석하고 기기가 검증한다(F-43). 대상이나 범위가 분명하지 않으면 그 부분만 묻는다(F-47).
5. 저장하면 지금 화면에 결과를 반영하고 바뀐 자리를 강조하며, 대화 영역에 결과 요약을 보인다(F-48). 묻는 문장이면 찾은 결과를 목록으로 보인다(F-43).
6. 사용자는 이어서 요청하거나 대화를 접고 모듈을 넓게 보며 작업을 이어 간다.

| 상태         | 동작                                                                                      |
| ------------ | ----------------------------------------------------------------------------------------- |
| 평소         | 한 줄 높이의 입력 바                                                                      |
| 입력 바 누름 | 입력 영역과 키보드가 열린다. 비어 있으면 예시 문장이 보인다                               |
| 되묻기       | 입력 영역 위에 짧은 질문과 선택지. 같은 입력창에 적어 답해도 된다                         |
| 처리 중      | 진행 상태만 보인다. 확정되지 않은 결과를 저장된 것처럼 그리지 않는다                      |
| 저장 완료    | 실제 화면에 결과를 반영하고 강조. 입력 영역 위에 결과 요약                                |
| 찾은 결과    | 입력 영역 위에 찾은 목록과 짧은 답(개수 · 빈 시간). 줄을 누르면 상세가 열린다             |
| 대화 접기    | 입력 바 한 줄로 돌아간다. 적던 문장은 남고, 답을 기다리던 요청은 대화 기록에 남는다(F-47) |

**규칙**

- **대화 영역은 모듈을 모두 가리지 않는다.** 따로 배경을 두어 구분하되 뒤 화면 전체를 흐리게 하지 않는다. 높이 · 색 · 강조 효과는 Figma가 정한다.
- **결과가 가려지면 화면을 옮겨 보인다.** 키보드나 대화 영역이 바뀐 자리를 가리면 모듈을 스크롤해 보이게 한다. 화면 밖의 결과를 보이려고 다른 날짜나 모듈로 끌고 가지는 않는다(F-48).
- **접어도 지우지 않는다.** 대화를 접거나 다른 모듈로 가도 적던 문장은 입력 바에 남는다.
- **예시 문장:** 대화 영역이 비어 있을 때 예시 문장 몇 개를 보인다. 누르면 입력 바에 채워지고 보내지는 않는다.
- **직접 입력:** 입력 바의 단추는 하나다. 입력이 비어 있으면 그 단추가 직접 입력(「+」)이고, 한 글자라도 적으면 같은 자리가 보내기로 바뀐다(접근성 이름도 함께 바뀐다, 4.6). 따로 선 직접 입력 단추는 두지 않는다. 직접 입력을 누르면 입력 화면의 종류를 고르는 메뉴가 뜨고, 고른 입력 화면(F-09)이 열린다. 할 일 · 노트 · 시간표 모듈에서는 메뉴 없이 그 모듈의 입력 화면(할 일 · 노트 · 시간표 아이템)을 바로 연다. 지금 화면의 날짜 같은 맥락이 초기값이 되고, 모아보기에서 연 컬렉션 안이면 그 컬렉션이 소속 초기값이다. AI를 쓰지 않거나 동의하지 않은 사용자의 길이다. 모양은 Figma가 정한다.
- **선택 맥락:** 아래 규칙을 따른다.
- 보낸 문장과 결과는 대화 기록(F-50)에 남는다.

**선택 맥락**

| 규칙                  | 내용                                                                                                                                                                           |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 무엇이 맥락인가       | 지금 모듈, 보는 날짜나 주, 대상 아이템                                                                                                                                         |
| 고르는 조작           | 아이템을 누르면 상세가 열린다(F-13). 상세가 열려 있으면 그 아이템을 고른 것이다. 상세에서도 AI 입력 바를 쓴다                                                                  |
| 보이게 한다           | 입력 바 위에 아이템과 회차 날짜를 함께 보인다(예: "선택한 항목: 영어 수업 · 11월 2일(월)"). 눌러 해제한다                                                                      |
| 두 가지 맥락을 나눈다 | 상세를 열어 고른 맥락은 "선택한 항목", 같은 대화에서 방금 만들거나 고친 아이템이 이어진 맥락은 "방금 고친 항목"처럼 다르게 보인다                                              |
| 언제 풀리나           | 상세를 닫으면 고른 맥락이 풀린다. 이어진 맥락은 대화를 접거나 다른 아이템을 고르면 끝난다. 보내기 전에 다른 모듈로 가면 적던 문장만 남고 맥락은 풀린다                         |
| 보낸 순간에 묶는다    | 요청은 보낸 순간의 모듈 · 날짜 · 대상에 묶인다. 그 뒤 화면을 옮기거나 상세를 닫아도 그 요청의 맥락은 바뀌지 않는다. 남겨 둔 질문에 나중에 답할 때도 처음 보낸 때의 맥락을 쓴다 |
| 보임과 고름을 나눈다  | 화면에 보이기만 하는 아이템은 수정 대상으로 정하지 않고 후보로만 쓴다                                                                                                          |
| 결과가 여럿이면       | 방금 결과가 여럿이면 어느 것도 저절로 이어지지 않는다. 결과 요약에서 한 줄을 누르면 그 결과가 맥락이 되고, 누르지 않고 "4시로 바꿔 줘"처럼 보내면 대상을 묻는다(F-47)          |
| 찾은 결과             | 같은 대화에서 찾은 목록은 "방금 찾은 항목"으로 맥락이 되어 "이거 다 금요일로 미뤄 줘"의 대상이 된다. 하나를 가리키는 문장이면 어느 것인지 묻는다(F-47)                         |
| 문장이 먼저다         | 문장에 다른 날짜나 아이템이 분명히 적혀 있으면 화면의 맥락보다 문장을 따른다                                                                                                   |
| 모호하면 묻는다       | 같은 이름의 아이템이 여럿이거나 반복의 어디까지인지 분명하지 않으면 그 부분만 묻는다(F-47)                                                                                     |

**예:** 시간표 모듈에서 이번 주 영어 수업 블록을 누르면 회차 상세가 열리고 입력 바 위에 "선택한 항목: 영어 수업 · 11월 2일(월)"이 보인다. "이번 주만 오후 7시로 옮겨 줘"를 보내면 그 회차만 옮긴다. 상세를 닫으면 시간표 모듈에서 옮겨진 블록이 강조돼 있다.

**직접 입력의 종류**

| 순서 | 메뉴 항목     | 입력 화면이 받는 것                                    |
| ---- | ------------- | ------------------------------------------------------ |
| 1    | 일정          | 시작 · 끝 · 종일 · 반복 · 장소 · 알람 등               |
| 2    | 할 일         | 상태(미완료로 시작) · 마감 · 우선순위 · 반복 · 알람 등 |
| 3    | 노트          | 본문                                                   |
| 4    | 시간표 아이템 | 시간대 목록 · 기간 · 장소 등                           |
| 5    | 일정 + 노트   | 시간과 본문. 본문은 비워도 된다                        |
| 6    | 할 일 + 노트  | 마감 · 우선순위와 본문. 본문은 비워도 된다             |
| 7    | 일정 + 할 일  | 시간과 마감 · 상태                                     |

아무것도 설정하지 않아도 바로 쓰도록 입력 화면 구성을 앱이 미리 제공한다. 구성은 서버 DB의 데이터다. 시간표 아이템 하나는 이 메뉴로 바로 만들고, 여럿을 한 번에 만들거나 불러올 때는 F-31 「시간표 만드는 페이지」를 쓴다.

### F-09. 입력 화면

아이템을 만들 때 뜨는 화면이다. 여러 성격을 함께 받아도 단계로 나뉘지 않고 **한 화면**이며, 칸은 묶음으로 보인다: 기본(이름 · 태그 · 색), 일정(시작 · 끝 · 종일 · 장소), 할 일(상태 · 마감 · 우선순위 · 예상 소요시간), 반복(일정이나 할 일이 있을 때), 알람(시각이 있을 때), 노트(본문), 시간표(시간대 목록 · 기간).

**동작 흐름**

1. 사용자가 어떤 자리에서 만들기를 시작한다. 그 자리가 실은 값(누른 날짜, 누른 칸의 요일 · 시각 등)이 초기값이 된다.
2. 값을 적고 저장하면 앱이 필수 칸을 검사하고, 비었으면 화면으로 돌아간다.
3. 아이템이 생기고 서버로 간다. 아이템은 기본 소속(F-40)에 든다.
4. 입력 화면을 연 자리로 돌아간다. 직접 입력에서 시작했으면 그때 보던 화면이고, 만든 아이템의 성격을 따라 모듈을 옮기지 않는다.

**규칙**

- **필수 칸:** 일정은 시작, 할 일은 상태, 노트는 본문, 시간표 아이템은 시간대다. 끝은 비면 아래 초기값을 쓴다. 이름은 어디서도 필수가 아니다(F-12). 직접 입력 메뉴의 일정 + 노트와 할 일 + 노트는 본문 필수를 끈다.
- **끝 시각의 초기값**은 시작에 예상 소요시간을 더한 값이고, 없으면 한 시간 뒤다. 종일이면 그날 하루를 덮는다.
- **취소:** 적은 것이 없으면 바로 닫고, 있으면 확인을 받는다. 한 줄에 적은 문장도 입력이다.
- **화면을 막는 입력 화면은 하나다.** 열린 채 다른 만들기를 시작하면 적은 것이 있을 때 확인을 받고 바꾼다. 겹침은 입력 화면 위의 확인 창 하나까지이고 ESC는 맨 위부터 닫는다.
- **입력 화면이 열려 있는 동안에는 AI 입력 바를 쓰지 않는다.** 입력 화면이 지금 화면을 덮는다(iPhone은 시트). 상세에서 AI 입력 바를 쓰는 것(F-08 선택 맥락 · F-13)과 다르다.
- 서버가 그 쓰기를 받아들이지 않으면 앱이 아이템을 되돌리고 무엇이 반영되지 않았는지 알린다.

**입구:** AI 입력 바의 직접 입력(F-08)과 캘린더 빈 칸 등 맥락이 있는 자리에서 연다. AI 결과의 직접 고치기는 새 입력 화면이 아니라 F-13 「아이템 상세와 바로 고치기」를 연다.

### F-10. 입력 화면 내려 두기 (iPhone)

입력 화면을 닫지 않고 내려 둔 채 다른 화면을 보는 기능이다. AI 입력 바의 대화 접기(F-08)는 문장을 남기는 동작이며 이 기능과 다르다.

**아직 정하지 않았다:** 이 기능을 MVP에 포함할지와 AI 입력 바 위에 내려 둘지. 포함한다면 다음 보관 규칙을 적용한다.

- 여럿을 내려 둘 수 있고 개수 제한은 없다. 적은 것이 없으면 내려 두지 않고 닫는다.
- 취소가 아니라서 확인을 거치지 않고, 화면을 막는 입력 화면으로 세지 않는다.
- 기기에 남아 앱을 끝내도 그대로다. 시스템의 화면 상태 복원에 맡기지 않고 앱이 지울 수 있는 사용자별 저장소에 둔다. 기기 사본의 하나라서, 사본과 보내지 않은 쓰기를 지우는 때(로그아웃 · 탈퇴 · 기기 끊김 · "내가 아니다")와 다른 계정이 로그인할 때 함께 지운다. 비밀번호 재설정 때는 보내지 않은 쓰기와 함께 봉해 둔다(F-03).

### F-11. 되돌리기 단추

삭제 · 미룸 · 고정 해제처럼 곧장 실행한 되돌릴 수 있는 동작 뒤에 화면 아래에 "삭제 되돌리기" · "미룸 되돌리기" · "고정 해제 되돌리기"를 잠깐 띄운다. 지운 뒤에는 휴지통에 30일 남는다는 것도 함께 알린다. iPhone에도 같은 단추를 자체 부품으로 두고 흔들어 실행 취소도 같은 동작을 부른다. 웹은 ⌘Z · Ctrl+Z도 같고, 글 입력 칸에 커서가 있으면 그 칸의 되돌리기가 먼저다.

AI가 만들거나 고치거나 지운 결과도 되돌릴 수 있다. 적용 범위와 이후 변경 보호는 F-48 「결과 요약과 변경 강조」를 따른다.

## 3.3 아이템

### F-12. 아이템과 속성

아이템에는 종류가 없다. 붙은 속성으로 성격이 정해지고, 한 아이템이 일정이면서 할 일이면서 노트일 수 있다.

| 속성   | 칸                                                                                                   | 있으면                                                                   |
| ------ | ---------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| 공통   | 이름 · 태그 · 색                                                                                     |                                                                          |
| 일정   | 시작 · 끝 · 종일 · 장소 · 표준 시간대                                                                | 캘린더의 그 날짜와 시각에 선다                                           |
| 할 일  | 상태 · 마감(날짜, 또는 날짜와 시각) · 우선순위(1 ~ 5, 1이 가장 높다) · 예상 소요시간(분) · 완료 시각 | 체크박스가 붙고 할 일 모듈에 선다(F-51)                                  |
| 반복   | 반복 규칙                                                                                            | 일정 · 할 일에 붙고 회차가 난다. 기준 날짜는 시작, 없으면 마감이다(F-23) |
| 알람   | 기준 시각보다 몇 분 전의 목록                                                                        | 시각이 있는 아이템(일정 · 할 일 · 시간표 회차)에 붙는다(F-41)            |
| 노트   | 본문(마크다운)                                                                                       | 본문 편집기가 붙고 노트 모듈에 선다(F-52)                                |
| 시간표 | 시간대 목록(요일 · 시작 시각 · 끝 시각) · 기간(시작일 · 종료일)                                      | 시간표 아이템이 된다(F-30)                                               |

**규칙**

- 아이템 상세에서 일정 · 할 일 · 노트 속성을 더하고 뺀다. 할 일을 더하면 상태가 미완료로 선다. 빼면 그 속성의 칸을 지우는데, 사용자가 적은 값이 있으면 먼저 알린다.
- **시간표 속성은 만들 때만 정한다.** 기간과 겹침 검사가 필요해서다. 일정을 시간표 아이템으로 바꾸려면 새로 만든다.
- **표준 시간대:** 아이템은 만들 때 계정의 기본 표준 시간대(F-46)를 갖는다. 기본 표준 시간대를 바꾸면 그 뒤에 만든 아이템만 새 값을 받고, 이미 있는 아이템은 그대로다. 시각 값(시작 · 끝 · 시각을 고른 마감)은 이 표준 시간대의 시각이고, 반복 회차의 날짜와 날짜 없는 아이템의 만든 날도 이 표준 시간대로 정한다(F-23 · F-26). 화면은 보는 기기의 표준 시간대로 바꿔 보인다. 종일 값과 날짜만 고른 마감은 표준 시간대 없이 날짜다(4.2).
- **색**은 필수가 아니고, 비면 소속 컬렉션의 색을 따른다. 스와치 이름(red · orange · amber · green · teal · blue · indigo · pink · gray)으로 저장하고 hex로 저장하지 않는다. 같은 스와치가 테마마다 다른 색이기 때문이다.
- **이름**은 필수가 아니다. 비어 있으면 본문 첫 줄을, 그것도 없으면 자리 표시 글자를 보인다. 글자는 Figma가 정한다.

### F-13. 아이템 상세와 바로 고치기

아이템을 누르면 상세가 열린다. 어느 모듈에서 열어도 같은 상세다. 웹은 빠른보기 팝오버, iPhone은 Apple 캘린더의 관례대로 연다.

- **상세에는 편집 모드가 없다.** 칸을 누르면 그 자리에서 고치고 칸마다 바로 저장한다. 웹 팝오버에도 [편집] 단추가 없다.
- iPhone에서 시각과 소요시간처럼 이어진 값은 칸을 꾹 누른 채 밀어 바꾸고 놓으면 저장한다. 피커도 그대로 두고, VoiceOver는 조절 동작으로 같은 일을 한다. 입력 화면도 같은 컨트롤을 쓴다.
- 저장은 화면에 먼저 반영하고, 서버는 바뀐 칸만 합친다.
- 표시 순서는 미리보기에 보이는 칸 → 장소 → 본문 → 나머지다. 아래에는 관련 아이템 목록(F-16)이 있다.
- 시간표 아이템의 상세에는 만들기 버튼이 둘 있다. 하나는 날짜를 골라 일정 + 노트를 만드는 입력 화면(시작 · 본문 필수)을, 다른 하나는 할 일 입력 화면을 연다. 두 화면 모두 시간표 아이템의 값을 가져오지 않고 기본값으로 열리며, 만든 아이템은 그 시간표 아이템과 출처 연결로 이어진다. 버튼 글자는 Figma가 정한다.

### F-14. 아이템 설정 메뉴

캘린더의 아이템(월력 칩 · 보드 줄 · 시간 축 블록)을 iPhone은 길게 눌러, 웹은 우클릭해 연다. 항목은 상세의 ⋯ 메뉴와 같은 목록이고 가진 속성으로 거른다: 할 일 상태 바꾸기 · 시간 정하기 · 보드로 옮기기 · 날짜 지우기 · 고정과 고정 풀기 · 상세에 붙은 만들기 버튼 · 반복 회차면 "반복 고치기" · 삭제(맨 끝).

iPhone 보드 줄 밀기는 이 메뉴의 지름길이다. 왼쪽으로 밀면 시간 정하기 · 삭제, 오른쪽으로 밀면 할 일 줄은 완료(완료면 미완료), 다른 줄은 고정이다. 시간 축 블록은 길게 누른 채 끌면 메뉴가 사라지고 옮기기가 된다.

### F-15. 지우기와 휴지통

**동작 흐름**

1. 상세나 아이템 설정 메뉴에서 삭제를 고른다. iPhone은 보드 줄과 할 일 모듈의 줄을 왼쪽으로 밀어서도 지운다.
2. 앱이 곧장 소프트 삭제하고 "삭제 되돌리기"를 띄운다.
3. 지운 아이템은 관련 목록에서 바로 빠지고, 노트의 위키링크는 "삭제됨"으로 보이며 누를 수 없다. 본문 글자와 연결 기록은 그대로다.
4. 휴지통에서 30일 안에 되살리면 관련 목록과 위키링크도 살아난다.
5. 30일 뒤 서버가 연결 기록 · 변경 이력 · 충돌 기록과 함께 물리 삭제한다. 미리 알리지 않는다.

**휴지통 규칙**

- 설정에서 연다. 지운 때가 늦은 것부터 남은 날과 함께 보인다. 30일은 서버가 삭제를 반영한 시각부터 센다.
- 함께 지워진 것은 함께 돌아온다. 지운 반복 마스터는 한 줄로, 컬렉션과 함께 지워진 아이템은 그 컬렉션 한 줄로 선다.
- 반복의 회차 하나를 지운 것은 휴지통에 서지 않고 되돌리기 단추로만 되살린다. 휴지통 비우기와 하나를 바로 지우는 길은 없다.

### F-16. 아이템 잇기와 관련 아이템 목록

아이템 상세 아래에 이어진 아이템이 "관련 N개"로 모인다. 연결 종류와 성격을 가리지 않고 같은 목록에 서며, 누르면 그 아이템으로 간다.

| 연결 | 저장 값      | 언제 생기나                                                                                                                                 |
| ---- | ------------ | ------------------------------------------------------------------------------------------------------------------------------------------- |
| 출처 | created_from | 상세의 만들기 버튼으로 만들 때 늘 생긴다. 관련 목록에서 이미 있는 아이템을 출처로 걸 때와, AI가 다른 아이템의 때를 기준으로 만들 때도(F-43) |
| 언급 | reference    | 노트 본문의 위키링크를 저장할 때 본문에 맞춰 생기고 사라진다                                                                                |
| 회차 | derived_from | 반복의 회차가 예외 회차가 될 때                                                                                                             |
| 미룸 | postponed_to | 할 일을 미룰 때 원본에서 이월본으로                                                                                                         |
| 나뉨 | split_from   | 반복을 적용 시작일로 나눌 때 옛 마스터에서 새 마스터로                                                                                      |

**규칙**

- 손으로 걸고 끊는 연결은 출처 하나다. 다른 연결은 그 동작이 만들고 지운다. 이을 아이템은 목록 안의 컨트롤로 받아 둔 워크스페이스에서 찾는다.
- 연결은 아이템 밖에 한 줄로 저장하고, 같은 (출발 · 도착 · 종류)는 하나만 남는다. 서버는 양쪽 모두 요청자의 것일 때만 받는다.
- 나뉘어 이어진 마스터들은 서로를 목록에 세우지 않고 사슬에 이어진 아이템을 함께 모은다. 목록에서 여러 개를 골라 한 번에 지울 수 있다.

**아직 정하지 않았다:** 이어진 아이템을 화면에서 선으로 잇는 시각화. 어느 보기에 둘지, 선 모양, 선을 눌러 가는 조작이 남았다.

## 3.4 할 일

### F-17. 할 일 상태와 체크박스

| 상태   | 저장 값   | 표시                                |
| ------ | --------- | ----------------------------------- |
| 미완료 | todo      | 빈 체크박스                         |
| 완료   | done      | 체크와 제목 취소선                  |
| 미룸   | postponed | 이월 표시                           |
| 취소됨 | cancelled | 제목 취소선과 완료와 다른 체크 표시 |

**규칙**

- **체크박스는 미완료와 완료만 오간다.** iPhone에서 할 일 줄을 오른쪽으로 밀어도 같고, 홈과 제공되는 홈 화면 위젯의 체크박스도 같다. 미룸이나 취소됨인 할 일은 체크박스로 바뀌지 않는다.
- **미룸과 취소는 메뉴로 한다.** 메뉴에서는 어느 상태로든 바로 바꾼다. 단추는 "완료로 표시" · "미완료로 표시" · "미룸으로 표시" · "취소됨으로 표시"이고, 되돌리기는 "미룸 되돌리기" · "취소됨 되돌리기"다.
- **완료 시각:** 완료로 바꾼 쓰기를 만든 기기의 시각을 남기고, 완료에서 벗어나면 지운다. 동기화에서 상태와 완료 시각은 한 칸이다.
- **취소됨은 지우지 않는 기록이다.** 자기 날의 캘린더에 그대로 서고 앱이 지우지 않는다. 취소는 할 일에만 있고, 일정의 회차를 안 하려면 지운다.
- **마감 표시:** 시작 없이 마감만 있는 할 일은 마감 날짜의 보드에 마감 표시로 서고 끌어 옮기지 않는다. 날짜만 고른 마감은 시각 없이 날짜로 저장하고, 종일 값처럼 어느 표준 시간대에서 보든 같은 날에 선다. 보는 기기의 오늘이 그 날짜를 지나야 밀린 할 일이다.

### F-18. 미루기

할 일을 미루면 원본은 미룸으로 남고 고른 날짜에 새 할 일(이월본)이 선다. 미룬 흔적을 지우지 않는 것이 요점이다.

**동작 흐름**

1. "미룸으로 표시"를 고르고 날짜를 고른다. 원래 시각이 기본이고 시각도 고칠 수 있다.
2. 원본은 postponed로 남는다.
3. 고른 날짜에 이월본이 미완료로 서고 원본과 미룸 연결로 이어진다. 이월본은 원본의 컬렉션과 마감을 물려받는다.
4. "미룸 되돌리기"가 뜬다.

**규칙**

- 시각이 없던 할 일은 그날 하루를 덮는 종일 값을 받아 보드에 선다. 여럿을 미루면 날짜 하나로 맞추고 시각은 저마다 둔다.
- **반복 할 일의 회차**는 날짜를 먼저 고르고 알림 창에서 고른다. "(고른 날)에 하기"는 회차를 미룸으로 두고 이월본을 반복 밖에 세운다. "다음 회차((날짜))로 넘기기"는 회차를 취소됨으로 두고 이월본을 만들지 않는다. 고른 날이 다음 회차의 날이면 넘기기만 보인다.
- **미룸 되돌리기**는 이월본이 미완료일 때만 된다. 이월본을 소프트 삭제하고 원본을 미완료로 되돌린다. 이월본을 고쳤으면 확인을 받고, 다시 미룬 것은 끝의 이월본부터 되돌린다.
- 미룬 원본을 메뉴로 바로 완료나 취소됨으로 바꾸면, 손대지 않은 미완료 이월본은 지운다.

**화면 예시:** 매주 하는 할 일의 회차를 내일로 미루면 "내일에 하기"와 "다음 회차(11월 6일)로 넘기기"가 뜬다. 오늘 · 내일 · 어제는 그 말로 적는다.

### F-19. 재조정 제안

계획이 틀어진 할 일에 앱이 옮길 빈 시간을 하나 제안하고, 사용자가 받아들이면 옮긴다.

**틀어진 할 일:** 상태가 미완료이면서 잡아 둔 칸이 지났거나(종일이면 그날이 끝나야), 칸 없이 마감이 지났거나, 날짜 없이 적었는데 만든 날이 지난 할 일이다. 반복 할 일의 회차는 제안하지 않는다.

**동작 흐름**

1. 홈의 밀린 할 일과 그 할 일의 상세에 제안 시간이 보인다.
2. 제안 시간을 누르면 시작과 끝이 그 시간으로 채워지거나 옮겨진다. 종일 할 일은 시각 할 일이 되고, 마감과 상태는 그대로다.
3. "다른 시간 고르기"는 재조정 창을 연다. 오늘부터 일주일 안의 같은 길이가 들어가는 빈 칸을 보이고 제안 칸을 미리 골라 둔다.
4. 제안에는 "완료로 표시"도 있다. 이미 하고 체크를 잊었을 수 있어서다.

**제안 칸:** 지금 이후 캘린더의 다른 아이템(반복 회차 포함)과 겹치지 않는 가장 이른 빈 시간이다. 길이는 예상 소요시간이고 없으면 한 시간이다. 종일 일정 · 끝 없는 아이템 · 취소됨은 칸을 막지 않는다. 기기 시각으로 23시부터 다음 날 하루 시작 시각(F-46)까지는 피한다. 기기가 계산한다.

**기획 의도:** 앱은 사용자가 누르기 전에는 아무것도 옮기지 않는다.

### F-20. 그날 · 그달 묶음 처리

그날이나 그달의 미완료 할 일(반복 회차와 날짜 없이 적은 할 일 포함)을 한꺼번에 처리한다. 그날 묶음은 완료 · 미룸 · 취소됨, 그달 묶음은 완료 · 취소됨이다. 그달 묶음은 캘린더 헤더의 ⋯ 메뉴에서 열고, 그날 묶음의 자리는 Figma가 정한다. 상태만 바꾸고 대상마다 상태 바꾸기를 하나씩 낸다. 밀린 반복 회차를 한 번에 건너뛰는 기능은 따로 없고 이것으로 한다.

### F-51. 할 일 모듈

할 일 성격이 있는 아이템을 모아 처리하는 모듈이다. 열면 오늘 할 일이 먼저 선다.

**동작 흐름**

1. 모듈 패널에서 할 일을 고르면 오늘 할 일이 열린다. 홈의 「오늘」 묶음에 서는 할 일과 같다(F-07).
2. 체크박스로 완료를 바꾸고(F-17), 줄을 누르면 그 자리에서 상세가 열린다(F-13).
3. 오늘 밖의 할 일(밀린 할 일 · 앞으로의 할 일 · 날짜 없는 할 일)도 이 모듈에서 본다. 묶음과 배치는 Figma가 정한다.

**규칙**

- **거르기와 정렬:** 상태(미완료 · 완료 · 미룸 · 취소됨)로 거르고, 마감일순 · 우선순위순 · 만든 순으로 정렬한다. 고른 값은 사용자별로 남고, 거르기와 정렬은 기기가 한다(4.4).
- 밀린 할 일의 줄에는 홈처럼 제안 시간이 붙는다(F-19).
- **반복 할 일:** 오늘 할 일과 밀린 할 일에는 회차마다 한 줄씩 선다(홈과 같다). 앞으로의 할 일에는 반복 할 일마다 가장 가까운 회차 한 줄만 선다. 그래서 앞으로의 할 일은 끝을 두지 않고 내일부터 모두 보인다(F-23).
- **iPhone 줄 밀기:** 오른쪽은 완료 토글, 왼쪽은 미룸과 삭제다. 반복 할 일의 줄에서 지우면 그 회차만 지우고 범위를 묻지 않는다(F-23).
- 일정이기도 한 할 일은 캘린더에도 선다. 아이템은 하나라 어느 쪽에서 고쳐도 함께 바뀐다(F-40).

## 3.5 노트

### F-21. 노트 편집기

본문은 마크다운으로 쓰고 기호를 치는 즉시 서식이 입혀진다(순수 WYSIWYG, 편집과 미리보기를 나누지 않는다).

- **서식:** 굵게 · 기울임 · 취소선 · 인라인 코드 · 링크, 리스트 들여쓰기와 내어쓰기, 에디터 자체의 되돌리기와 다시 실행.
- **슬래시 명령:** `/`를 치면 메뉴가 뜬다. MVP는 8종이고 제목 · 리스트 · 체크박스 · 코드 블록 · 인용이 정해졌다.
- **이름:** 비어 있으면 본문 첫 줄을 쓴다.
- **저장은 늘 마크다운 원본 텍스트다.** 입력이 멈추면 쓰기로 넘기고(iOS 앱은 기기에 먼저, 웹은 서버로), 타이핑마다 서버 쓰기를 만들지 않는다.
- **붙여넣기:** 외부 HTML은 마크다운으로 바꾸고 허용된 서식만 남긴다.
- **동기화:** 본문은 칸 하나라서 두 기기가 함께 고치면 문단으로 합치지 않고 충돌로 남겨 하나를 고른다(F-45).

**아직 정하지 않았다:** 슬래시 명령의 나머지 3종.

### F-22. 위키링크

본문에서 `[[`를 치면 아이템 자동완성이 뜨고, 고른 아이템이 `[[item:id|alias]]` 형식으로 들어간다. 화면에는 alias가 링크로 보인다.

- 저장할 때 본문의 위키링크를 읽어 언급 연결을 맞춘다. 읽는 일은 기기가 하고 연결의 등록 · 삭제를 본문 쓰기와 함께 보낸다. 서버는 본문을 해석하지 않는다.
- 가리킨 아이템이 지워지면 "삭제됨"으로 보이고 누를 수 없다. 이름이 바뀌어도 alias는 그대로다. 둘 다 사용자가 쓴 글자를 앱이 고치지 않기 위해서다.
- **복사**하면 모든 플랫폼에서 평문(위키링크만 alias 글자로 바꾼 마크다운)을 클립보드에 싣는다. 같은 계정의 앱 안에서는 iOS와 웹을 오가도 위키링크가 남는다(형식은 구현이 정한다). 붙여넣는 사람의 아이템이 아니면 alias 글자로 풀고, 외부 앱에는 alias 글자로만 남는다.

### F-52. 노트 모듈

노트 성격(본문)이 있는 아이템을 모아 읽고 쓰는 모듈이다.

**동작 흐름**

1. 모듈 패널에서 노트를 고르면 노트 목록이 최근 수정순으로 열린다.
2. 줄을 누르면 그 자리에서 상세가 열리고 본문을 바로 쓴다(F-21).

**규칙**

- **정렬:** 최근 수정순 · 만든 순 · 이름순. 고른 값은 사용자별로 남고, 정렬은 기기가 한다(4.4).
- 본문 안의 글로 찾는 것은 전역 검색(F-39)이 한다.
- 일정이나 할 일이기도 한 노트는 그 모듈에도 선다. 아이템은 하나라 어느 쪽에서 고쳐도 함께 바뀐다(F-40).

## 3.6 반복

### F-23. 반복과 회차

반복 규칙을 가진 아이템이 마스터다. 일정 · 할 일 · 시간표 아이템이 같은 방식을 쓴다. 일정과 할 일의 반복은 n일마다 · 매주 · 매월(같은 날짜, 예: 매달 15일) · 매년(같은 날짜, 예: 매년 3월 2일) 가운데 고른다.

- **회차는 저장하지 않는다.** 앱이 보는 범위 안에서만 규칙을 계산해 그린다.
- **회차 하나를 고치거나 끌어 옮기거나 지우면 그 회차만 바뀌고 범위를 묻지 않는다.**
- **손댄 회차만 예외 회차로 저장하고, 손댄 칸만 값을 갖는다.** 나머지는 마스터를 계속 따라간다. 시각 · 장소 변경, 메모 붙이기, 연결 대상 삼기, 색 변경, 할 일 회차의 완료 · 미룸 · 취소가 모두 예외 회차를 만든다.
- **회차 연산은 iCalendar 표준을 그대로 쓴다.** 지우기는 EXDATE, 바꾸기는 RECURRENCE-ID, 더하기는 RDATE다. 할 일 회차의 취소는 바꾸기의 하나다.
- 반복 할 일의 회차 날짜는 시작, 없으면 마감 기준이다. 두 기기가 같은 회차를 따로 예외로 만들어도 서버에는 하나만 남는다.
- **그 달에 없는 날은 건너뛴다.** 매달 31일은 31일이 있는 달에만, 매년 2월 29일은 윤년에만 회차가 난다. iCalendar 표준(RFC 5545)과 같아서 ICS로 주고받아도 회차가 같다. 29일 · 30일 · 31일을 고르면 그 날이 없는 달에는 회차가 없다고 알린다.
- **회차는 아이템의 표준 시간대에서 계산한다(F-12).** 그래서 표준 시간대가 다른 기기에서도 같은 회차가 같은 날짜에 선다. 시간표 아이템은 표준 시간대 없는 요일과 시각이다(4.2).

### F-24. 반복 전체 고치기와 지우기

직접 조작으로 반복 전체를 바꾸는 자리는 **마스터 상세**다. AI 입력에서도 대상과 범위를 명확히 지정해 같은 연산을 요청할 수 있다(F-43). 맨 위의 적용 시작일이 어디부터 바꿀지 정한다.

**동작 흐름**

1. 회차 상세의 ⋯ 메뉴나 아이템 설정 메뉴에서 "반복 고치기"를 고른다.
2. 마스터 상세가 열린다. 적용 시작일의 기본은 들어온 회차의 날짜이고, 회차 없이 열었으면(모아보기 · 검색 · 관련 목록) 오늘이다.
3. 칸을 고치면 바로 저장된다. 적용 시작일과 같거나 뒤인 첫 회차부터 적용되고 반복이 거기서 둘로 나뉜다. 두 마스터는 나뉨 연결로 이어지고 지난 회차는 그대로다. 열린 상세는 새 마스터로 넘어간다.
4. "처음부터"를 고르면 나누지 않고 전체를 고친다. 지난 회차도 다시 계산된다고 알린다.

**규칙**

- 서버 저장 연산의 이름은 "이후 전체"와 "전체"이고, 화면 글자는 적용 시작일과 "처음부터"다.
- 적용 시작일 뒤에 회차가 없으면 "처음부터"로만 고치고, 앞에 회차가 없으면 나누지 않고 고친다. 회차가 있는지는 규칙이 내는 자리로 세고, 지운 회차도 센다.
- **예외 회차의 사용자 값은 지킨다.** 마스터의 시각이나 요일을 바꾸면 예외와 지운 회차도 같은 만큼 옮겨진다. 짝이 없거나 다른 회차와 같은 자리에 놓이면 맞추는 창에서 고르게 하고, 닫으면 알림 목록에 풀지 않은 충돌로 남는다(F-45).
- 이미 나뉜 반복을 고치면 이어진 마스터 가운데 고치기 전과 같은 값인 칸만 따라 바뀐다. 따로 바꾼 값은 두고 알린다.
- **지우기도 같은 날짜를 따른다.** 실행 전에 확인을 받는다. 전체를 지우면 예외 회차와 나뉜 앞뒤 마스터도 함께 지운다. 그 마스터를 출처로 만든 아이템은 기본으로 남기고, 확인 창에서 함께 지우기를 고를 수 있다.

시간표 아이템은 나누는 경계가 주의 시작이다(F-33).

## 3.7 캘린더

### F-25. 캘린더 보기

**월력**이 기본이다. 연력은 월력으로 옮기는 도구이고, 일 상세는 월력에서 날짜를 눌러 들어간다. 웹은 주간 보기(F-29)를 더 둔다. iPhone 주간 보기는 MVP 밖이다(6장). 캘린더를 열면 마지막에 쓴 보기로 열고, 보기를 바꿔도 보던 날짜를 지킨다.

- **월력:** 달 사이를 연속 스크롤로 오간다(스냅 없음). 웹은 범위 이동 단추도 둔다. 칸마다 일자 숫자와 일정 칩이 선다.
- **일정 칩:** 날짜 · 시간 · 제목과 캘린더 색 · 아이템 색을 함께 보인다. 캘린더 색은 소속 컬렉션의 색이다. 할 일이면 상태 넷을 구분한다.
- **시작 요일:** 일요일과 월요일 가운데 고른다.
- **지난 날 미완료 표시:** 지난 날 칸에 틀어진 할 일(F-19)이 남아 있으면 표시를 단다.
- **연력:** 달을 누르면 그 달의 월력이다. 날마다 아이템 수를 색 농도로 보이고, 취소됨과 날짜 없는 아이템은 세지 않는다.
- **이동과 거르기:** 오늘로 가기와 날짜 골라 가기가 있고, 오늘은 보는 기기의 날짜다. 켜진 컬렉션의 아이템만 보인다. 컬렉션을 켜고 끄는 상태는 캘린더와 시간표가 따로 갖고(F-32), 새 컬렉션은 켜진 채 생긴다(F-46).
- **공휴일:** 한국 공휴일을 월력 · 연력 · 일 상세에 읽기 전용으로 보인다. 모양은 Figma가 정한다. 아이템이 아니어서 고치거나 옮기지 않고, 연력의 수와 빈 시간 계산(F-19)에 넣지 않는다. 설정에서 켜고 끄며 처음에는 켜져 있다(F-46).

**아직 정하지 않았다:** 공휴일 자료를 앱에 넣을지 서버가 내려줄지.

**넘칠 때:** 월력 칸에 다 들어가지 않으면 "+N"으로 접는다.

### F-26. 일 상세: 보드와 시간 축

위에 보드, 아래에 시간 축이 있다. 헤더의 날짜를 누르면 월력으로 돌아간다. 처음 여는 위치는 오늘이면 지금 시각, 다른 날이면 하루 시작 시각이고 그 줄이 위에서 1/3 자리에 온다. iPhone은 시간 축을 좌우로 밀어 어제와 내일로 간다.

**보드**

- 그날의 종일 아이템, 날짜 없는 아이템, 마감 표시가 선다. 화면에 "시간 없는 아이템"이라는 이름은 보이지 않는다.
- 접힌 보드에 다 보이지 않으면 "N개 더 보기"로 알리고, "모두 보기"로 펼치면 그날의 시간 있는 아이템도 선다. iPhone에서 펼친 보드는 화면을 차지한다.
- 기본 순서는 고정한 아이템 → 성격 그룹(할 일이 맨 앞) → 만든 순서다. 사용자가 정렬과 그룹을 고르면 남는다.

**고정:** 고정한 아이템은 보드 맨 앞에 서고 풀 때까지 남는다. 메뉴로 하고, iPhone 보드에서는 할 일이 아닌 줄을 오른쪽으로 밀어서도 한다. 고정 표시를 한 번 누르면 풀린다. 고정은 아이템의 칸이 아니라 사용자의 보기 상태로 저장하고, 홈의 고정 목록(F-07)에 모인다.

**시간 축:** 겹치는 일정은 시작 순(같으면 만든 순)으로 가장 왼쪽 빈 레인에 놓고 폭을 똑같이 나눈다. 끝과 시작이 같으면 겹치지 않는다. 레인 수에 상한이 없다.

**날짜 없는 아이템:** 시작 · 마감 · 반복이 모두 없으면 만든 날(생성 시각을 아이템의 표준 시간대로 자른 날짜. 표준 시간대를 옮겨도 바뀌지 않는다)의 보드에 서고, 그 날은 저장하지 않는다. 다른 날로 옮기면 그날의 종일 값이 생기고, 메뉴에서 날짜를 지우면 다시 만든 날로 돌아간다. 날짜를 정하지 않았다는 사실을 남기려는 것이다.

**끝이 없는 아이템:** 종일로 시작했으면 그날 하루짜리로 보드에, 시각으로 시작했으면 그 시각에 길이 0인 표지로 선다.

### F-27. 캘린더에서 만들기

| 동작                           | iPhone                                       | 웹                                                      |
| ------------------------------ | -------------------------------------------- | ------------------------------------------------------- |
| 시간 축의 빈 시각              | 길게 누르고 떼면 그 시각에 만든다            | 누르면 그 시각에 만든다                                 |
| 시간 축에서 길이를 정해 만들기 | 길게 누른 채 끈다                            | 빈 시간대를 끈다                                        |
| 월력 날짜 칸의 빈 곳           | 만들지 않는다(누르면 일 상세)                | 그 날짜의 종일 아이템. 일자 숫자는 일 상세(사이드 패널) |

| 월력 날짜 칸 더블클릭          | 없음(더블탭을 쓰지 않는다)                   | 일정 + 할 일 입력 화면을 그 날짜 종일로 연다            |

웹의 시간 축 · 보드 더블클릭은 기본 동작 없이 비워 둔다. iPhone에서 그냥 누르기는 아무것도 하지 않는다.

### F-28. 끌어 옮기기 · 길이 조절 · 시간 정하기

**시간 축 끌기:** 스냅은 10분이고 끝은 길이를 지켜 따라간다. 다른 일정과 겹쳐도 막지 않는다. 보드에 놓으면 그날의 종일 값이 된다.

|         | iPhone                                                       | 웹                                                     |
| ------- | ------------------------------------------------------------ | ------------------------------------------------------ |
| 시작    | 길게 누르면 메뉴가 뜨고, 누른 채 끌면 메뉴가 사라지며 옮긴다 | 끈다                                                   |
| 화면 끝 | 위아래는 자동 스크롤, 왼쪽 끝은 어제, 오른쪽 끝은 내일       | 다른 날로 넘기지 않고 스크롤 영역 안에서만 자동 스크롤 |
| 취소    | 원래 자리나 놓을 수 없는 자리에 놓으면 돌아간다              | 취소 구역에 놓거나 ESC                                 |

- **길이 조절:** 블록 테두리를 끈다. 스냅 10분이고 iPhone은 Apple 캘린더의 관례를 따른다.
- **웹 월력 끌기:** 다른 날짜 칸으로 옮긴다. 스냅 1일이고 시각은 지킨다. iPhone 월력에서는 끌지 않는다.
- **시간 정하기:** 보드에서 시간 축으로 끌어 놓지 않는다(iPhone은 시간 축이 다 보이지 않아서이고 웹도 같은 규칙). 메뉴나 iPhone 보드 줄의 왼쪽 밀기로 시작을 고른다. 초기값은 오늘이면 다음 정시, 다른 날이면 하루 시작 시각이다.

반복 회차를 끌면 그 회차만 옮겨진다. 마감 표시는 끌지 않는다.

### F-29. 웹 주간 보기와 사이드 패널

웹에만 있다. 요일 7개 열로 한 주를 보이고 위의 종일 줄이 보드다. 표시 모드는 타임그리드(시각이 좌표, 처음 기본)와 일정 나열(그날 아이템을 시간순으로 쌓는다) 둘이고 마지막 선택을 기억한다. 일정 나열 모드에서는 다른 요일 열로 옮기기만 되고 시각과 길이는 상세에서 고친다.

**우측 사이드 패널**은 그날의 일 상세(보드 + 시간 축)를 옆에 띄운 것이고 조회와 수정을 함께 한다. 일자 숫자를 누르면 열린다.

**아직 정하지 않았다:** 일정 나열 모드에서 한 열이 넘칠 때의 처리("+N" 접기나 열 높이 늘리기). 한 주를 세로 스크롤 없이 읽어야 해서 열 안 스크롤은 뺐다.

## 3.8 시간표

### F-30. 시간표와 시간표 아이템

**시간표 아이템**은 요일마다 시간대를 가진 매주 반복 아이템이다. 기간(시작일 · 종료일)을 아이템마다 갖는다. 시작일을 비우면 만든 날, 종료일을 비우면 끝이 없다. 어느 컬렉션에든 들고, 시간표 모듈이 켜진 컬렉션의 시간표 아이템을 한 주 격자로 모아 보인다(F-32). 시간표를 따로 묶는 단위는 없다.

**규칙**

- **시간표 아이템은 시간대를 여럿 가진다.** 시간대는 요일과 날짜 없는 시작 · 끝 시각이고, 같은 요일에 두 번도 아이템 하나다.
- **회차는 아이템의 기간 안에서만 난다.** 날짜마다 그 요일의 시간대마다 하나씩 생기고, 캘린더에는 마스터가 아니라 회차가 선다.
- **시작일이 지난 날이어도 그날부터 회차가 난다.** 앱이 기간을 고치자고 제안하지 않는다.
- **같은 컬렉션의 시간표 아이템끼리는 겹칠 수 없다.** 같은 아이템의 시간대끼리도 그렇다. 기간이 겹치는 아이템끼리만 보고, 만들 때와 마스터 상세에서 시간대나 기간을 고칠 때 검사해 겹치는 값은 받지 않는다. 다른 컬렉션의 시간표 아이템과는 겹쳐도 받고, 시간표 모듈에서 레인으로 나눠 그린다. 회차 하나의 시각을 캘린더·시간표 상세·AI 입력으로 고쳐 겹치게 하는 것은 막지 않는다. 겹친 회차의 표시는 F-26과 F-32를 따른다.
- **이번 주부터 놓기:** 오늘이 기간 안이고 기간 전체로는 지난 회차와 겹치지만 이번 주부터는 겹치지 않으면, 시작일을 이번 주 월요일로 놓고 그렇게 놓았다고 알린다.
- **색**은 만들 때 같은 컬렉션의 시간표 아이템이 안 쓴 색을 자동으로 고르고(다 쓰면 가장 적게 쓴 색), 나중에 바꿀 수 있다.
- 캘린더와 시간표 모듈에서 켜고 끄는 단위는 컬렉션이다(F-40). 두 모듈이 각자 켜고 끄며, 새 컬렉션은 두 곳 모두에서 켜진 채 생긴다. 그래서 시간표 만드는 페이지(F-31)에서 새 컬렉션과 함께 만든 시간표 아이템이 바로 선다. 다른 컬렉션으로 옮겨도 기간과 회차는 그대로다.

### F-31. 시간표 만드는 페이지

시간표 아이템 여럿은 만드는 페이지에서 한 번에 만든다.

**동작 흐름**

1. 시간표 모듈의 ⋯ 메뉴나 빈 상태 안내에서 새 시간표를 고른다.
2. 넣을 컬렉션(있는 것이나 새 컬렉션)과 기간을 정한다. 이 기간이 이 페이지에서 만드는 아이템 모두의 기간이 된다.
3. 시간표 아이템을 입력 화면으로 차례로 더하거나 "불러오기로 채우기"(F-34)로 채운다. 페이지의 요일 × 시각 격자에 바로 보인다.
4. 만들기를 확정하면 아이템(새 컬렉션이면 그 컬렉션도)이 한 묶음으로 저장된다. 모두 서거나 하나도 서지 않는다.

**규칙:** 확정 전에는 아무것도 저장하지 않고, 나가면 적은 것이 있을 때 확인을 받는다. 불러오기(F-34)는 이 페이지 안에서 한다. 시간표 아이템 하나는 이 페이지 없이 직접 입력(F-08)으로도 만든다.

### F-32. 시간표 모듈

시간표 아이템은 시간표 모듈에서 본다. 모듈은 켜진 컬렉션의 시간표 아이템을 **고른 주**의 실제 회차로 한 격자에 그린다.

**동작 흐름**

1. 시간표 모듈을 열면 이번 주가 열린다. 앞뒤 주로 옮겨 갈 수 있다.
2. 블록을 누르면 그 회차의 상세가 열린다. 캘린더에서 연 회차 상세와 같다.
3. 빈 칸을 누르면 그 요일과 시각이 채워진 시간표 아이템 입력 화면이 열린다.
4. 헤더의 ⋯ 메뉴: 새 시간표(F-31), 불러오기(F-34), 보일 컬렉션 켜고 끄기(캘린더와 따로인 시간표 모듈의 상태), 표시 요일.

**규칙**

| 대상                                 | 시간표 모듈에서                                                      |
| ------------------------------------ | -------------------------------------------------------------------- |
| 손대지 않은 회차                     | 규칙대로 그 자리에 선다                                              |
| 시각이나 장소를 바꾼 회차(예외 회차) | 바뀐 자리에 서고 "이번 주만" 같은 표시를 단다. 모양은 Figma가 정한다 |
| 지운 회차(F-23의 회차 지우기)        | 그리지 않는다                                                        |
| 겹친 회차                            | 일 상세의 시간 축처럼 레인을 나눠 폭을 나눈다(F-26)                  |

- **"취소"와 "지우기"를 섞지 않는다.** 할 일 회차의 취소는 상태(cancelled)로 남고, 일정 · 시간표 회차를 하지 않는 것은 회차 지우기다. 지운 회차를 표시로 남기는 일은 MVP 밖이다(6장).
- **반복 전체를 고치는 길:** 회차 상세의 ⋯ 메뉴 "반복 고치기"(F-24)가 마스터 상세를 연다. 시간표 아이템이면 적용 시작일의 기본은 그 회차가 든 주의 월요일이다(F-33).
- 모듈 안에서는 블록을 끌거나 길이를 바꾸지 않는다. 회차 시각은 상세나 AI 입력 바로 고친다.
- 세로축은 기본 09:00 ~ 18:00이고 밖의 회차까지 넓히며 스크롤한다. 표시 요일은 시간표 모듈의 보기 설정이고(기본 월 ~ 금), 그 밖의 요일에 회차가 있으면 그 열을 더한다. 오늘 열과 지금 시각을 표시하고, 블록에는 이름과 장소를 보인다.
- 빈 상태에는 "시간표를 추가해 보세요"와 새 시간표 · 불러오기를 보인다.

### F-33. 시간표 아이템 고치기와 지우기

F-24를 따르되 **나누는 경계가 주의 시작**이다. 시간표 아이템의 주는 캘린더 시작 요일 설정과 상관없이 월요일에 시작한다.

| 상황                                                                  | 고치면                                                                                                                                                 |
| --------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 적용 시작일이 월요일(시간표 모듈에서 연 회차가 든 주의 월요일이 기본) | 그 주 월요일 0시에서 나누고 지난 주는 그대로 둔다                                                                                                      |
| 적용 시작일이 다른 요일                                               | 고른 회차부터 그 주 끝까지는 옛 마스터의 예외로 새 값을 담고 다음 주 시작에서 나눈다. 다음 주부터 회차가 없으면 나누지 않고 그 주의 남은 회차만 바꾼다 |
| 이번 주에 만든 아이템이고 적용 시작일이 이번 주 안                    | 나누지 않고 그 아이템을 고친다                                                                                                                         |
| 지난 시간표 아이템(이번 주부터 회차가 없다)                           | "처음부터"로만 고친다                                                                                                                                  |

**규칙**

- 시간대 하나를 옮기면 그 시간대만 움직인다. 바꾼 시간대가 다른 아이템이나 같은 아이템의 다른 시간대와 겹치면 받지 않는다. 견주는 기간은 나누면 경계 뒤, 아니면 그 아이템 전체다.
- **지우기**는 마스터 상세에서 하고 적용 시작일을 따른다. 시간표 모듈의 회차에서 열었으면 기본은 그 회차가 든 주의 월요일이다. 적용 시작일 전 회차는 남기고 그날부터 뒤에 이어진 마스터까지 지운다. 이번 주에 만들었거나 앞에 회차가 없으면 통째로 지운다. 실행 전에 확인을 받는다.
- 회차 하나를 고치거나 지우는 것은 회차 상세에서 한다. 캘린더와 시간표 모듈 어디서 열어도 같다. 아이템을 다른 컬렉션으로 옮겨도 기간과 회차는 그대로다(F-40).

### F-34. 시간표 불러오기 (애드온)

다른 앱의 시간표 화면 캡처로 시간표 아이템을 한꺼번에 만든다. 첫 시장을 위한 애드온이고 코어는 이것 없이 완결된다.

**동작 흐름**

1. 시간표 모듈의 ⋯ 메뉴나 빈 상태 안내에서 불러오기를 고르면 만드는 페이지(F-31)가 열리고, 그 안에서 캡처를 올린다.
2. 이름 · 요일 · 시간 · 장소를 인식한다. 기기 안 모델이 있으면 기기에서, 없으면 서버에서 한다.
3. 결과를 보정 격자에 띄운다. 같은 아이템으로 보이는 블록은 한 아이템의 시간대로 묶인다.
4. 사용자가 고치고 무엇을 한 아이템으로 볼지 확인해 확정한다.
5. 만들기를 확정할 때 다른 아이템과 함께 한 묶음으로 저장된다(모두 또는 하나도, F-31).

**규칙:** 불러온 아이템은 만드는 페이지에서 정한 컬렉션과 기간을 따른다. 정확도 목표치는 두지 않고 보정 격자가 흡수한다. 서버 인식은 처음 쓰기 전에 동의를 받고(동의하지 않거나 설정에서 끄면 기기 모델만, F-46), 응답 시간 상한과 사용자별 호출 한도(값은 구현)를 둔다. 웹 페이지를 긁어 오는 방식은 약관과 법적 위험 때문에 쓰지 않는다.

## 3.9 한눈에 보기와 홈 화면 위젯

### F-35. 한눈에 보기와 iPhone 홈 화면 위젯

앱 안의 한눈에 보기는 **홈**(F-07)이 맡고, iPhone 홈 화면 위젯은 앱을 열지 않고 보는 보조 수단이다. 위젯이 없어도 홈에서 오늘과 밀린 할 일을 모두 보고 처리할 수 있어야 한다. 위젯은 새 표시를 만들지 않고 홈의 줄을 줄여 쓴다.

**동작 흐름**

1. 사용자가 iPhone 홈 화면에 베드락 위젯을 놓는다.
2. 위젯이 기기의 워크스페이스 사본으로 그린다.
3. 위젯을 눌렀을 때의 진입 위치는 F-36 「위젯 둘」의 앱 밖 진입 범위를 따른다.

**규칙**

- 위젯은 서버에 묻지 않고 기기 사본으로 그린다. 사본이 바뀌면 위젯을 다시 그린다.
- 위젯에서 바꾸는 것은 앱 안에도 있는 길로만 한다(체크, 제안 시간으로 옮기기).
- 웹에는 위젯이 없다. 웹의 한눈에 보기도 홈이 맡는다.

**앱 안의 정보 위치**

| 정보                                         | 위치                                                        |
| -------------------------------------------- | ----------------------------------------------------------- |
| 오늘 · 밀린 할 일 · 이번 주 마감 · 고정 목록 | 홈(F-07)                                                    |
| 고른 주의 시간표                             | 시간표 모듈(F-32)                                           |
| 최근 메모                                    | 노트 모듈(F-52). 최근 수정순이 기본이다                     |
| 다가오는 일정                                | 캘린더 월력(F-25). 별도의 앞으로 7일 목록 보기는 MVP에 없다 |

### F-36. 위젯 둘

아래는 위젯을 제공할 때의 구성이다. 특정 화면으로 여는 동작은 앱 밖 진입을 MVP에 포함하는 경우에 적용하며, 포함하지 않으면 홈으로 연다.

| 위젯       | 보여 주는 것                     | 누르면                               | 빈 상태                    |
| ---------- | -------------------------------- | ------------------------------------ | -------------------------- |
| 오늘       | 홈의 다음 일과 오늘 줄을 줄인 것 | 캘린더 일 상세                       | "오늘 일정·할 일이 없어요" |
| 밀린 할 일 | 틀어진 할 일(F-19)과 제안 시간   | 제안 시간은 옮기기, 그 밖은 그 할 일 | "밀린 할 일이 없어요"      |

- **앱 안 이동과 앱 밖 진입을 나눈다.** 홈 · 결과 요약 · 알림 목록에서 아이템을 여는 것은 앱 안 이동이라 MVP다. 위젯이나 기기 알림을 눌러 앱 밖에서 특정 화면으로 들어오는 길은 앱 밖 진입이다. 웹 주소로 열기는 있다(4.1).

**아직 정하지 않았다:** 위젯을 MVP에 넣을지. 앱 밖 진입(위젯 · 기기 알림을 눌러 특정 모듈 · 아이템 열기)을 "iOS 앱의 딥링크와 앱 URL 스킴"(6장 MVP 밖)에서 떼어 MVP에 넣을지. 넣지 않으면 위젯과 알림은 앱을 홈으로 연다.

## 3.10 모아보기 · 검색 · 컬렉션

### F-37. 모아보기 목록

컬렉션과 그 안의 아이템을 파일 탐색기처럼 보는 모듈이다. 컬렉션이 폴더, 아이템이 파일에 해당하고, 기능도 파일 탐색기 정도에서 멈춘다. 할 일과 노트를 거르고 정렬하는 일은 할 일 모듈(F-51)과 노트 모듈(F-52)이 맡는다.

- **처음 화면:** 컬렉션 목록이다. 컬렉션을 열면 그 안의 아이템이 한 목록으로 선다.
- **새 컬렉션:** 컬렉션 목록 끝에서 만든다. 이름 · 색 · 아이콘을 받는 것은 설정의 「컬렉션」 탭과 같다. 이름 바꾸기와 지우기는 설정에서만 한다(F-40).
- **성격 배지:** 일정 · 할 일 · 노트 · 시간표 넷이고 한 아이템에 둘 이상 붙을 수 있다. 날짜가 없다는 것은 배지가 아니다.
- **반복 아이템**은 한 줄로 서고 회차를 펼치지 않는다.
- **정렬:** 이름순 · 최근 수정순 · 만든 순. 컬렉션 목록과 컬렉션 안의 목록에 함께 쓴다. 거르기는 두지 않는다.
- **정렬은 기기가 한다.** 서버는 사용자가 적은 글을 해석하지 않는다(4.4).
- 줄을 누르면 그 자리에서 상세가 열린다. 반복 아이템은 마스터 상세다.
- 여러 아이템을 골라 다른 컬렉션으로 옮기거나 지운다(F-38).
- 고른 정렬은 사용자별로 남는다.

### F-38. 일괄 선택

모아보기에서 여러 아이템을 골라(하나씩 · 범위 · 전체, 키보드로도) 다른 컬렉션으로 옮기거나 지운다. 파일 탐색기에서 파일을 옮기고 지우는 것과 같다.

- 옮기기는 아이템마다 소속을 바꾸는 쓰기다. 옮긴 뒤에도 되돌리기를 띄운다(F-11, 컬렉션 삭제는 F-40). 지우기는 소프트 삭제이고 서버에 대량 삭제 한 번으로 보낸다. 하나를 지울 때처럼 확인 없이 지우고 「삭제 되돌리기」를 띄운다(F-15).
- 옮길 곳 목록 끝에서 새 컬렉션을 만들 수 있다. 칸은 모아보기의 새 컬렉션과 같고, 만들면 고른 아이템을 바로 그곳으로 옮긴다.
- 색 · 태그 · 상태 · 기간을 한 번에 고치는 일괄 편집은 MVP 밖이다(6장).

### F-39. 전역 검색

이름 · 본문 · 태그 · 속성 값으로 아이템을 찾아 상세를 연다. 웹의 자리는 웹 모듈 오가기(4.1)와 함께 정하고, iPhone 자리는 Figma가 정한다.

- **받아 둔 워크스페이스에서 찾는다.** 연결이 없어도 되고 서버 검색은 없다.
- **검색어는 서버에 남기지 않는다.** iOS는 그 기기에만, 웹은 탭이 열린 동안만 둔다. 브라우저 자동 완성도 끈다.
- 검색 칸에서 앱 명령도 실행한다. 명령 목록은 코드가 정한다.

### F-40. 컬렉션

아이템은 **컬렉션 하나에만 속하고**, 어디에도 속하지 않은 아이템은 없다. 컬렉션에는 종류가 없어서 일정 · 할 일 · 노트 · 시간표 아이템을 함께 담고, 하나의 프로젝트처럼 쓴다.

예: "기본", "동아리", "운동 루틴", "근무표". 컬렉션 하나에 모임 일정 · 준비할 일 · 회의 노트 · 시간표 아이템이 함께 들 수 있다.

- 가입할 때 기본 컬렉션이 하나 생기고 지울 수 없다.
- **기본 소속:** 만들 때 고른 컬렉션에 들고, 고르지 않으면 기본 컬렉션에 든다. 만드는 페이지(F-31)에서 만든 시간표 아이템은 그 페이지에서 정한 컬렉션에 든다. 컬렉션에 종류를 두지 않는 것은 성격은 바뀌는데 소속은 만들 때 정해져 어긋나기 때문이다.
- 컬렉션마다 색(비지 않는다)과 아이콘이 있다. 보기에서 컬렉션을 켜고 끈다. 컬렉션을 만들고 고치고 지우는 곳은 설정의 「컬렉션」 탭이다(F-46). 만들기는 모아보기의 컬렉션 목록과 옮길 곳 목록에서도 한다(F-37 · F-38). 컬렉션 하나를 모아 보는 것은 모아보기에서 그 컬렉션을 열어서 한다(F-37).
- **이름:** 컬렉션 이름은 비울 수 없다. 새로 만들면 「새 컬렉션」이 채워져 있고, 색과 아이콘도 기본값이 채워져 있다(값은 Figma가 정한다). 아이템 이름은 비워 둘 수 있지만(F-12) 컬렉션은 목록과 옮길 곳에서 이름으로 가리기 때문이다.
- 컬렉션 삭제는 확인 창을 거친다. 지우면 안의 아이템도 함께 휴지통으로 가고 함께 돌아온다(F-15). MVP의 권한은 주인 하나다.
- **소속과 수정:** 아이템은 하나라 어느 모듈에서 고쳐도 모든 자리에서 함께 바뀐다. 결과 요약(F-48)과 상세는 속한 컬렉션을 보인다.
- **옮기기와 지우기는 다르다.** 다른 컬렉션으로 옮기면 소속만 바뀌고 아이템은 그대로다. 시간표 아이템은 기간과 회차도 그대로다(F-33). 문장이 옮기기인지 지우기인지 분명하지 않으면 묻는다(F-47).
- 컬렉션 안의 컬렉션은 MVP 밖이다(6장).

## 3.11 알람 · ICS · AI 해석

### F-41. 알람과 알림 목록

**알람:** 시간 칸을 가진 아이템(일정 · 할 일 · 시간표 회차)의 알람을 기기가 예약해 기기의 알림으로 울린다. iOS는 로컬 알림, 웹은 브라우저 알림이고 서버는 알람을 보내지 않는다.

- **알람 칸:** 기준 시각보다 몇 분 전인지를 여러 개 담는 목록이다. 0이면 그 시각에 울린다. 기준 시각은 시작, 없으면 마감이고, 종일이거나 날짜만 고른 마감이면 그날의 하루 시작 시각(F-46)이다. 반복 회차는 마스터의 목록으로 계산하고, 회차에서 바꾸면 예외 회차가 된다(F-23). 문장으로도 정한다(F-43).
- **기본 알림:** 설정에서 종류마다 기본 알림을 정한다. 종류는 시각 일정 · 종일 일정 · 시각을 고른 할 일 · 날짜만 고른 할 일이다. 아이템을 만들 때(직접 입력 · 캘린더 · AI 입력) 알람을 따로 정하지 않았으면 그 종류의 기본값을 알람 칸에 채운다. 채운 뒤에는 아이템의 값이라, 기본값을 바꿔도 이미 만든 아이템은 바뀌지 않는다. 일정이면서 할 일이면 일정의 기본값을 쓴다. ICS로 가져온 아이템은 파일의 알림을 따른다. 처음 값은 구현이 정한다.
- 기기마다 따로 울린다. 웹은 베드락 탭이 열려 있을 때만 울린다. 서버 없이 브라우저가 예약 알림을 울리는 표준이 없어서다.
- iOS 예약 수 한도를 넘으면 가까운 것부터 예약하고 울린 만큼 채운다. 아이템이 바뀌면 예약을 다시 맞추고, 연결이 없어도 예약한 알람은 울린다.
- 알림에는 아이템 이름을 싣는다. 알림 권한이 없으면 알림 목록에만 남는다.

**알림 목록:** 대화 기록과 설정 패널에서 연다(F-50). 두 종류로 묶는다.

- **아이템 알림:** 울린 알람.
- **시스템 알림:** 받아들여지지 않은 쓰기, 지워진 대상에 닿은 쓰기, 풀지 않은 충돌(F-45), 서버 안내. 서버 안내는 푸시가 아니라 앱이 서버와 주고받을 때 받아 온다(서버가 보내는 푸시는 6장).
- 울린 알람과 쓰기 결과는 기기마다 보관한다(웹은 탭이 열린 동안). 풀지 않은 충돌과 서버 안내는 서버에 있어서 모든 기기에 같게 보이고, 충돌은 고를 때까지 남는다.
- 모양은 Figma와 코드가 정한다.

**아직 정하지 않았다:** 어떤 상황(시작 전 · 마감 임박 · 밀린 할 일)에 어떤 강도로 알릴지, 웹 탭이 닫히면 안 울린다는 것을 화면에서 알릴지.

### F-42. ICS 가져오기와 내보내기

다른 캘린더 앱과 .ics 파일로 일정을 주고받는다. 회차 예외까지 잃지 않는다. 가져오기와 내보내기는 설정의 「컬렉션」 탭에서 한다(F-46).

**동작 흐름**

1. 가져오기: 사용자가 파일과 넣을 컬렉션을 고른다. 앱이 일정 · 반복 · 회차 예외를 읽어 한 쓰기로 보내고, 서버는 전부 저장하거나 하나도 저장하지 않는다.
2. 내보내기: 사용자가 컬렉션을 고른다. 앱이 캘린더에 일정이나 회차로 뜨는 것만 쓴다. 시작이 없는 반복 할 일은 싣지 않는다.

**규칙**

- **회차 예외는 표준 그대로다.** 지운 회차는 EXDATE, 바꾼 회차는 RECURRENCE-ID, 더한 회차는 RDATE이고, 취소한 할 일 회차는 STATUS:CANCELLED를 단 RECURRENCE-ID다.
- **UID:** 가져온 일정은 파일의 UID를 남겨 내보낼 때도 쓰고, 앱에서 만든 일정은 아이템 id로 만든다. 한 파일에서 UID는 마스터마다 하나다.
- **다시 가져오면** UID로 찾아 새로 만들지 않고 갱신한다. 마지막으로 가져온 값과 칸마다 견줘, 가져온 뒤 사용자가 고친 칸은 덮지 않고 알린다. 앱에서 손댄 회차를 파일이 지우면 들이지 않고 알린다.
- **STATUS:CANCELLED를 가져오면** 원래 아이템에서 그 회차가 취소됨이면 취소됨으로, 아니면 회차 삭제로 받는다. 다른 앱에서 지운 회차가 취소선으로 다시 서지 않게 하려는 것이다.
- 일정의 바쁨 · 한가 표시(TRANSP)는 베드락에 칸이 없어 가져올 때 버린다. 빈 시간은 F-19의 규칙으로 센다.
- 같은 UID가 다른 컬렉션으로 들어오면 원래 아이템을 갱신하고 소속은 바꾸지 않는다.
- **시간대가 여럿인 시간표 아이템**은 시간대마다 일정으로 갈라 내보내고 같은 아이템이라는 표시를 확장 속성에 싣는다. 다시 가져오면 UID로 찾지 않고 고른 컬렉션에 따로 선다.

### F-43. 문장 AI 해석

AI 입력 바에 적은 문장을 AI가 해석해 아이템을 **하나 이상 만들거나 고치거나 지운다.** 미루기와 알람도 같은 문장에서 정한다. 일정을 묻는 문장에는 받아 둔 아이템에서 찾아 답한다(아래 「조회」). 기기가 검증을 마친 결과만 저장하고, 대상과 범위가 분명하면 확인 단계 없이 바로 저장한다. 한 문장의 결과는 **한 묶음**으로 저장한다.

**동작 흐름**

1. 사용자가 AI 입력 바에 문장을 적고 보낸다.
2. 기기가 선택 맥락(F-08), 지침(F-46), 그리고 기존 아이템을 고치거나 지우는 문장에 대비해 받아 둔 워크스페이스에서 고른 후보 아이템 몇 개를 문장과 함께 보낸다.
3. 서버가 AI에 보내 정해진 구조의 결과(만들 아이템 · 고칠 아이템과 범위 · 지울 아이템과 범위 · 찾을 조건 · 물을 것 · 할 수 없음과 이유)를 받는다.
4. 기기가 결과를 검증한다: 고칠 대상이 지금도 있고 보낸 때와 같은지, 값이 말이 되는지(끝이 시작보다 앞 등), 범위가 분명한지, 꼭 필요한 값이 있는지.
5. 아래 「저장 · 되묻기 · 기본값」대로 묻는다(F-47). 물을 것이 남아 있는 동안에는 아무 아이템도 저장하지 않는다.
6. 모든 결과가 확정되면 만들기 · 고치기 · 지우기를 한 묶음으로 저장한다. 하나라도 실패하면 묶음 전체를 반영하지 않는다.
7. 저장하면 결과 요약과 변경 강조를 보인다(F-48).

**저장 · 되묻기 · 기본값**

이 표가 AI 결과를 언제 저장하고 언제 묻는지의 기준이다. 다른 절은 이 표를 가리킨다.

| 상황                                                                                  | 처리                                                                                                                             |
| ------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| 한 문장의 모든 결과가 확정됐다(새 아이템의 값이 다 있고, 고칠 대상과 범위가 분명하다) | 한 묶음으로 바로 저장하고 결과 · 바꾸기 전과 뒤 · 되돌리기를 보인다                                                              |
| 대상이 여럿이거나, 반복의 이번 한 번인지 앞으로 전체인지 분명하지 않다                | 그 부분만 묻는다. 답이 모일 때까지 같은 문장의 다른 결과도 저장하지 않는다                                                       |
| 반복 전체를 지우거나 여러 아이템을 지운다                                             | 한 번 묻는다. 직접 조작도 반복 전체를 지울 때는 확인을 받는다(F-24). 하나를 지우는 분명한 요청은 바로 저장하고 되돌리기를 보인다 |
| 묻는 문장이다                                                                         | 저장하지 않고 찾은 결과를 보인다(아래 「조회」)                                                                                  |
| 만들기 · 고치기 · 지우기 · 찾기로 옮길 수 없다                                        | 이유를 한 줄로 알리고 문장을 입력 바에 남긴다                                                                                    |
| 생략할 수 있는 값                                                                     | 비워 두거나, 기본값이 정해진 칸이면 기본값을 쓴다                                                                                |
| 기본값을 쓴 값                                                                        | 기본값을 썼다는 것을 결과 요약에 보인다(예: 끝 시각은 시작 1시간 뒤)                                                             |
| 의도를 정하는 데 꼭 필요한데 기본값이 없는 값                                         | 지어내지 않는다. 묻거나, 그 값 없이 둘 수 있는 길을 준다(F-47)                                                                   |

**규칙**

- **지어내지 않는다.** 문장과 선택 맥락에 근거한 값만 쓴다. 기본값은 이미 정해진 칸에만 쓴다: 끝 시각(F-09), 소속(F-40), 할 일 상태(미완료).
- **꼭 필요한 값:** 일정은 시작이다. 시작 없이 적은 일정은 시각을 지어내지 않는다. 이름은 필수가 아니지만, 무엇을 만들지 내용이 없는 문장("할 일 하나 만들어 줘")은 빈 아이템을 지어내지 않고 묻는다.
- **날짜가 빠진 시각은 보던 날짜 하나로 풀 수 있을 때만 푼다.** "오후 2시"처럼 날짜 없이 시각만 적었을 때, 보낸 순간의 화면이 날짜 하나를 가리키면(홈은 오늘, 일 상세는 그날, 선택 맥락의 회차는 그 날짜) 그 날짜를 쓰고 그렇게 정했다는 것을 결과 요약에 보인다. 입력 화면이 연 자리의 값을 초기값으로 쓰는 것(F-09)과 같은 결이다. 월력 · 시간표 주간 격자 · 모아보기처럼 날짜 하나를 가리키지 않으면 날짜를 묻는다. 날짜도 시각도 없는 할 일은 날짜 없는 아이템이 된다.
- **반복의 범위는 기존 규칙으로 옮긴다.** "이번 주만"은 그 회차만 고친다(F-23). "앞으로 계속"은 적용 시작일로 반복 전체를 고친다(F-24, 시간표 아이템은 F-33).
- **"취소"는 대상에 따라 옮긴다.** 할 일이면 취소됨(F-17), 일정 · 시간표 회차면 지우기다(F-32).
- **날짜만 있는 할 일:** 날짜만 말하면 그날 종일 값으로, "까지"라고 하면 마감으로 넣는다. 지침에 다르게 적었으면 지침을 따른다.
- **조회:** 묻는 문장은 AI가 찾을 조건(기간 · 성격 · 상태 · 컬렉션 · 이름이나 태그에 든 말 · 빈 시간)으로 바꾸고, 기기가 받아 둔 워크스페이스에서 찾아 대화 영역에 목록과 짧은 답(개수 · 빈 시간)을 보인다. 빈 시간은 재조정 제안(F-19)과 같은 계산이다. 찾은 결과는 서버와 AI에 보내지 않고, 저장하는 것이 없어 되돌리기가 없다. 찾은 목록은 같은 대화의 맥락이 된다(F-08).
- **시간 의존:** 다른 아이템의 때를 기준으로 삼는 요청("회의 끝나면", "발표 1시간 전에")은 기준 아이템을 고칠 대상처럼 찾고, 요청한 때의 값으로 한 번 정한다. 결과 요약에 무엇에 맞췄는지 보이고, 두 아이템을 출처 연결로 잇는다(F-16). 기준 아이템이 나중에 옮겨져도 따라 움직이지 않는다(6장).
- **지침:** 사용자가 설정에 적은 지침(F-46)을 요청마다 함께 보낸다. 지침은 해석 습관과 기본값만 바꾸고, 이 절의 저장 · 되묻기 · 안전 규칙은 바꾸지 못한다. 문장에 분명히 적힌 것이 지침보다 먼저다.
- **고치거나 지울 수 있는 것은 기기가 보낸 후보와 선택 맥락의 아이템뿐이다.** AI가 다른 아이템을 가리키면 저장하지 않고 묻는다. 후보를 고르는 기준은 구현이 정하고, 조회처럼 AI가 만든 조건으로 기기가 찾는 방식도 쓸 수 있다.
- **답을 만드는 도중의 값은 저장하지 않는다.** 처리 중에는 진행 상태만 보이고, 저장은 검증을 마친 뒤 한 번 한다.
- **한 묶음은 끝까지 한 묶음이다.** 의도를 모두 확인한 것과 저장이 모두 성공한 것은 다르다. 서버가 묶음의 일부라도 받아들이지 않으면 기기에서도 묶음 전체를 되돌리고 알린다(F-44의 되돌리기와 같은 결). 일부만 저장하는 방식으로 조용히 대신하지 않는다.
- **AI 출력은 정해진 구조로만 받는다**(구조화 출력 · 도구 호출). 구조가 깨진 응답은 실패로 본다.
- **해석은 서버가 한다.** 기기 안 모델로 해석하는 것은 MVP 밖이다(6장).
- **동의:** 처음 보내기 전에 무엇을(4.3 「AI 해석에 보내는 것」) 어디로(서버와 외부 AI 서비스) 보내는지와 보낸 문장 · 결과가 대화 기록으로 남는다는 것(F-50)을 알리고 동의를 받는다. 동의하지 않으면 AI 입력 바는 직접 입력(F-08)과 같이 동작한다. 동의는 설정에서 언제든 끄고(F-46), 끄면 동의하지 않은 것과 같다.
- 응답 시간 상한과 사용자별 호출 한도(값은 구현)를 둔다. 입력과 결과는 로그에 남기지 않고, 사용자가 보는 대화 기록(F-50)으로만 둔다.
- 해석하지 못해도 문장을 잃지 않는다(F-49).
- 문장으로 알람도 정한다(F-41의 알람 칸).

**구현 전에 확인한다:** 서버가 AI 결과의 만들기 · 고치기 · 지우기(반복 회차 예외 · 반복 나누기 포함)를 한 묶음으로 전부 저장하거나 하나도 저장하지 않을 수 있는지. 묶음 저장 요청을 재전송해도 생성·수정·삭제·반복 나누기를 중복 적용하지 않는지 함께 확인한다. 시간표 만들기(F-31)와 ICS 가져오기(F-42)가 묶음으로 저장된다는 것만으로는 이 경우까지 된다고 보지 않는다. 안 되면 구현을 시작하기 전에 이 절을 다시 정한다.

**화면 예시:** 캘린더의 11월 4일(수) 일 상세에서 "오후 2시에 팀 회의 잡아 주고, 같은 날 보고서 보내기 할 일도 넣어 줘"를 보내면 그날 14:00 ~ 15:00 팀 회의와 그날의 할 일 하나를 만든다. 일 상세에 둘이 강조되고, 결과 요약은 "팀 회의 · 11월 4일 오후 2:00 (날짜는 보던 날, 끝 시각은 1시간 뒤로 정함)"과 "보고서 보내기 · 11월 4일 할 일" 두 줄이다.

## 3.12 동기화와 설정

### F-44. 오프라인과 동기화

로그인하면 앱이 워크스페이스를 통째로 받아 두고, 검색 · 거르기 · 정렬 · 재조정 제안은 받아 둔 것으로 기기에서 한다.

|                | iOS 앱                                                     | 웹                                                     |
| -------------- | ---------------------------------------------------------- | ------------------------------------------------------ |
| 받아 둔 데이터 | 기기에 사본. 사본을 먼저 그리고 뒤에서 갱신                | 탭 메모리에만                                          |
| 연결이 없을 때 | 만들고 고치고 지운다. 기기에 먼저 반영하고 연결되면 보낸다 | 읽기만 한다. 새 쓰기는 막고 알린다                     |
| 보내던 쓰기    | 연결되면 다시 보낸다                                       | 탭이 열린 동안 다시 보낸다. 남은 채 닫으려 하면 알린다 |

**칸 단위로 합친다.** 다른 칸을 고친 두 변경은 모두 남고 같은 칸이 부딪치면 충돌(F-45)이다. 컬렉션 소속은 칸 하나, 회차 예외 날짜는 날짜 하나가 칸 하나다. 반복 규칙 · 시간대 목록 · 알람 목록 · 태그 목록은 통째로 칸 하나이고, 태그가 부딪치면 기기가 두 목록의 합집합을 제안한다. 할 일 상태와 완료 시각은 한 칸이다.

**규칙**

- 서버가 받아들일 수 없는 쓰기(검증 실패 · 권한 없음 · 물리 삭제된 대상)는 다시 보내지 않는다. 기기에서 그 쓰기와 그것에 기대는 뒤 쓰기를 되돌리고 알린다. 다시 보내는 것은 연결 실패와 서버의 일시 오류뿐이다.
- 다른 기기가 지운 대상에 닿은 쓰기는 물리 삭제 전이면 버리지 않고 반영한 뒤, 지워졌다고 알리고 되살리기를 제안한다.
- 기기에서 만들 때 id는 기기가 정한다. 같은 생성을 다시 보내면 한 번만 반영하되, 다른 사용자의 행과 부딪치면 그 행을 고치지 않는다.
- 웹 탭은 쓰기와 받아 오기에 그 탭의 계정을 싣고, 서버는 세션의 계정과 다르면 받지 않는다. 웹 탭은 다시 보일 때와 정한 간격마다 세션을 확인해 끊김을 늦지 않게 받는다. 로그인과 로그아웃은 같은 브라우저의 다른 탭에도 알린다.
- iOS 앱에 로그인을 확인할 값이 없는데 사본이 남아 있으면 그리지 않고 사본과 보내지 않은 쓰기를 모두 지운다.
- **세션 만료:** iOS는 사본과 보내지 않은 쓰기를 남기고 같은 계정으로 다시 로그인하면 보낸다. 웹은 워크스페이스를 버리고, 보내지 못한 쓰기의 수를 로그인 화면으로 가기 전에 알린다. 그 쓰기는 같은 탭에서 같은 계정으로 이메일 로그인을 하거나, 같은 브라우저의 다른 탭에서 같은 계정으로 로그인했다는 알림을 받으면 보낸다. 그 탭에서 구글 · Apple로 다시 로그인하면 잃는다.
- **같은 기기에 다른 계정이 로그인:** iOS는 앞 사용자의 사본을 지우고 보내지 않은 쓰기만 봉해 두며, 30일 안에 돌아오지 않으면 그것도 지운다. 웹은 탭에 받아 둔 것을 버린다.
- **비밀번호 재설정으로 로그인이 끝남:** iOS는 사본을 지우고 보내지 않은 쓰기만 봉해 둔다. 같은 계정이 새 비밀번호로 다시 로그인하면 보내고, 다른 계정이 로그인하거나 30일 안에 돌아오지 않으면 지운다(F-03).

**아직 정하지 않았다:** iOS 앱 기기 저장소의 용량 상한과 넘칠 때의 정책. 보내지 않은 쓰기는 지우는 대상이 아니다.

### F-45. 충돌 알림과 고르기

두 기기가 같은 칸을 다른 값으로 바꾸면 서버는 사용자가 고를 때까지 어느 값도 버리지 않는다.

**동작 흐름**

1. 두 기기가 같은 칸을 다른 값으로 바꾼다. 같은 값이면 충돌이 아니다. 이름 · 본문 · 장소 · 태그는 서버가 값을 견주지 않아서, 두 값이 같은지는 기기가 가린다.
2. 서버는 먼저 도착한 값을 칸에 두고 진 쓰기를 풀지 않은 충돌로 남긴다.
3. 모든 기기가 서버 값에 충돌 표시를 달고, 알림 목록의 시스템 알림으로 알린다(F-41). 진 쪽도 조용히 바뀌지 않는다.
4. 사용자가 어느 기기에서든 알림이나 충돌 표시를 눌러 후보 하나를 고르면, 다른 기기의 알림 목록에서도 빠진다.

**규칙**

- 후보는 서버에 있어서 로그아웃 · 앱 삭제 · 기기 분실에도 사라지지 않는다. 충돌 중인 칸을 또 고치면 후보가 더해진다. 충돌만 따로 모으는 보관함 화면은 두지 않고, 풀지 않은 충돌은 알림 목록에 고를 때까지 남는다.
- 회차나 시각이 부딪치면 그 주의 달력 위에서 고른다. 함께 부딪친 시작과 끝은 앱이 한 쌍으로 보이고 함께 보낸다(서버의 충돌은 칸 단위 그대로).
- 반복 마스터를 바꾸거나 ICS를 다시 가져와 맞지 않게 된 회차 예외도 충돌이다. 가리킬 회차를 고르거나 버려서 풀고, 버리면 그 예외를 소프트 삭제한다.

**기획 의도:** 오프라인에서 쓴 값이 조용히 사라지면 사용자는 앱을 믿지 못한다.

### F-46. 설정

바꾼 값은 사용자별로 서버에 남아 어느 기기에서도 같다. OS 권한과 웹의 아이디 저장은 그 기기에 남는다.

| 탭             | 무엇을 바꾸나                                                                                         |
| -------------- | ----------------------------------------------------------------------------------------------------- |
| 계정 세부      | 프로필, 기기 목록(F-05), 탈퇴(F-06)                                                                   |
| 단축키         | 키보드 단축키                                                                                         |
| 외형           | 테마(라이트 · 다크), 밀도(첫 출하는 고정)                                                             |
| 캘린더         | 시작 요일(일 · 월), 하루 시작 시각, 기본 표준 시간대(F-12), 종류별 기본 알림(F-41), 공휴일 표시(F-25) |
| 모아보기       | 모아보기 설정                                                                                         |
| 컬렉션         | 만들기 · 이름 · 색 · 아이콘 · 지우기(F-40), ICS 가져오기 · 내보내기(F-42)                             |
| AI 지침        | AI 요청마다 함께 보내는 글(F-43). 비워 둬도 된다                                                      |
| 접근성 및 권한 | 접근성과 알림 등 권한, AI 해석 · 캡처 서버 인식 동의 켜고 끄기(F-43 · F-34)                           |

- **하루 시작 시각:** 기본 07:00, 0시 ~ 12시의 정시에서 고른다. 일 상세를 다른 날로 열 때의 위치와 재조정 제안이 피하는 밤의 끝이 따른다. 시간대 없는 시각이고, 날짜 경계는 0시 그대로다.
- **기본 표준 시간대:** 새 아이템이 받는 표준 시간대다(F-12). 처음 값은 가입한 기기의 표준 시간대이고 여기서 바꾼다. 바꾸면 그 뒤에 만든 아이템만 새 값을 받는다. 화면은 이 값과 상관없이 보는 기기의 표준 시간대로 보인다(4.2).
- **밀도:** 보기마다 촘촘 · 표준 · 여유. 첫 출하는 기본값 고정(월력 촘촘, 나머지 표준)이고 고르는 칸은 그 뒤에 붙이되, 값을 담을 자리는 처음부터 둔다.
- **보기 상태**(표시 모드 · 정렬 · 그룹 · 거르기 · 컬렉션 켜고 끄기 · 패널 · 고정)는 사용자별로 서버에 남는다. 컬렉션 켜고 끄기는 캘린더와 시간표가 각자 끈 컬렉션 목록으로 남기고, 빈 목록이면 모두 보인다. 그래서 새 컬렉션은 보이는 채 생긴다. 검색어는 서버에 남기지 않는다. 휴지통도 설정에서 연다.
- **지침:** 글 칸 하나이고 길이 상한은 구현이 정한다. 비워 둬도 모든 기능이 동작하고 처음 실행에 묻지 않는다. 해석 습관과 기본값만 바꾼다(F-43). 사람이 쓴 글이라 서버에 암호화해 둔다(4.4).

## 3.13 AI 입력과 결과

### F-47. 되묻기

AI 결과를 그대로 저장할 수 없을 때 그 부분만 짧게 묻는다. 언제 묻는지는 F-43 「저장 · 되묻기 · 기본값」이 정한다.

**동작 흐름**

1. 대화 영역에 무엇을 묻는지 한 줄과 선택지가 뜬다. 질문이 여럿이면 몇 번째인지 보인다.
2. 사용자가 선택지를 고르거나 입력 바에 직접 적어 답한다.
3. 답이 모두 모이면 F-43대로 한 묶음으로 저장하고 결과를 보인다(F-48). 그 전에는 아무 아이템도 저장하지 않는다.

**규칙**

- **의도를 가르는 질문을 먼저 한다.** 대상("영어 수업이 둘이에요: 월요일 · 수요일")과 범위("이번 주 수업만 · 다음 주부터 계속")가 먼저다.
- **선택지 수는 정하지 않는다.** 맥락(그 시각이 비었는지, 앞뒤 일정, 반복 규칙)으로 근거를 댈 수 있는 후보만 보이고, 선택지마다 고른 이유를 한 줄로 단다. 직접 적어 답하는 길은 늘 있다.
- **건너뛰어도 지어내지 않는다.** 꼭 필요한 값의 질문을 건너뛰면 그 값을 기본값으로 채워 저장하지 않는다. 일정의 시각을 묻는 질문에는 "날짜 없이 두기"를 선택지로 둘 수 있다. 고르면 날짜 없는 아이템(F-26)으로 저장하고 그 사실을 결과 요약에 보인다.
- 답하지 않고 대화를 접거나 로그아웃해도 아이템은 저장하지 않는다. 문장 · 질문 · 이미 한 답은 대화 기록(F-50)에 "답을 기다림"으로 남아 어느 기기에서든 다시 열어 이어 답할 수 있다. 이어 답할 때도 처음 보낸 때의 맥락(F-08)과 기준 시각 · 시간대를 쓴다. 늦게 이어 답해 푼 날짜가 이미 지났거나 고칠 대상이 그사이 바뀌었으면 F-49의 표와 같이 다룬다.
- 같은 요청은 한 번만 저장한다. 다른 기기에서 먼저 답해 저장했으면 나중 답은 저장하지 않고 그 결과를 보인다.
- 분명한 요청까지 매번 확인하지 않는다.

### F-48. 결과 요약과 변경 강조

저장한 결과를 실제 화면에 반영하고, 대화 영역에 전체 결과를 한 목록으로 보인다. 사용자를 결과마다 다른 화면으로 끌고 다니지 않는다.

**동작 흐름**

1. 저장하면 지금 화면에 있는 결과를 그 자리에서 강조한다. 새로 만든 아이템은 "새로 만듦", 고친 아이템은 "고침"이다. 지운 아이템은 화면에서 빠지고 요약에 "지움"으로 선다.
2. 대화 영역에 결과 요약이 뜬다. 결과가 여럿이어도 한 목록이다.
3. 지금 화면 밖의 결과(다른 날짜 · 다른 모듈)는 요약에 위치를 보이고 "해당 위치 보기"를 단다. 누르면 그 자리로 가고, 뒤로 가기로 원래 화면과 대화로 돌아온다.
4. 사용자는 이어서 요청하거나 대화를 접고 그 모듈에서 작업을 이어 간다. 홈으로 옮기지 않는다.

| 결과                      | 보이는 법                                          |
| ------------------------- | -------------------------------------------------- |
| 지금 화면에 보이는 아이템 | 그 자리를 강조하고 요약의 줄과 잇는다              |
| 다른 날짜 · 모듈의 아이템 | 요약에 위치를 보이고 "해당 위치 보기"              |
| 여러 결과                 | 한 목록. 줄마다 상세 보기 · 직접 고치기 · 되돌리기 |
| 기존 아이템을 고친 결과   | 바꾼 값의 전과 뒤, 적용 범위                       |
| 지운 결과                 | 요약에만 선다. 되돌리기로 휴지통에서 되살린다      |

요약 한 줄의 예:

> 영어 수업 · 이번 주 월요일만
> 오후 6시 → 오후 7시
> 되돌리기 · 직접 고치기

**규칙**

- **강조는 색만으로 하지 않는다.** "새로 만듦" · "고침" · "지움" 꼬리표를 함께 단다. 모양은 Figma가 정한다.
- **직접 고치기**는 그 아이템의 상세(F-13)를 연다.
- 찾은 결과(F-43 「조회」)는 저장한 것이 없어 이 절의 강조와 되돌리기를 쓰지 않는다.
- **되돌리기는 그 결과 하나를 그 요청 직전 상태로 돌린다.** 만든 것은 휴지통으로 보내고(30일, F-15), 지운 것은 휴지통에서 되살린다. 고친 것은 그 요청이 바꾼 칸마다 요청 직전 값으로 돌린다. 회차라면 요청 전에 예외 값이 있던 칸은 그 값으로 돌리고, 그 요청으로 처음 생긴 예외 값만 지운다. 다른 칸의 예외는 그대로 둔다.
  - 예: 영어 수업 이번 주 회차를 오후 6시 → 7시(요청 1) → 8시(요청 2)로 고친 뒤 요청 2를 되돌리면 7시로 돌아온다. 이어서 요청 1을 되돌리면 그 회차의 시각 예외가 지워져 마스터의 6시를 따른다.
- **나중 변경을 조용히 덮지 않는다.** 되돌릴 칸에 이후 변경이 남아 있으면(사용자 · 다른 기기 · 다른 요청) 되돌리지 않고 이유를 알린 뒤 직접 고치기를 연다. 뒤 요청을 정상적으로 되돌려 앞 요청 직후 상태로 복원한 경우에는 앞 요청도 순서대로 되돌릴 수 있다. 값만 우연히 같아졌다는 이유로 이후 변경이 없다고 판단하지 않는다. 만든 아이템을 사용자가 고친 뒤 되돌리면 확인을 받는다.

**아직 정하지 않았다:** 반복 전체를 적용 시작일로 나눠 고친 결과(F-24)의 되돌리기. 나뉜 두 마스터를 다시 합치는 연산이 지금 명세에 없다.

### F-49. 정리 대기

해석할 수 없을 때도 적은 문장을 잃지 않는다. 문장을 지키는 것과 나중에 실행하는 것은 따로다.

**동작 흐름**

1. 연결 없음 · 서버 오류 · 시간 초과 · 한도로 해석하지 못하면, 문장을 그대로 날짜 없는 아이템(본문이 문장)으로 저장하고 "정리 대기"를 단다. 기준 시각(처음에는 적은 시각)과 그때 기기의 시간대를 함께 남긴다.
2. 홈에 정리 대기 줄로 보인다. 연결이 돌아오면 다시 시도를 권한다.
3. 사용자가 다시 시도하면 그 아이템의 지금 본문을 기준 시각과 그 시간대로 다시 해석한다.
4. 해석 결과는 F-43대로 검증해 저장하거나 묻고, 결과 요약으로 보인다.
5. 저장되면 정리 대기 아이템은 휴지통으로 가고 결과 요약에 그 사실과 되돌리기를 보인다. 다시 해석해 보니 묻는 문장이면 찾은 결과를 보이고 정리 대기 아이템은 휴지통으로 간다. 사용자가 그 아이템에 본문 밖의 칸을 더했으면 지우지 않고 정리 대기 표시만 뗀다.

**규칙**

| 상황                                                       | 처리                                                                                                                                                                                         |
| ---------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| "내일 · 이번 주" 같은 상대 날짜                            | 기준 시각과 그 시간대로 푼다. 본문을 고치지 않았으면 처음 적은 시각이다                                                                                                                      |
| 사용자가 본문을 고쳤다                                     | 기준 시각을 본문을 마지막으로 고친 시각과 그때 시간대로 바꾼다. 다시 시도한 결과 요약에는 푼 날짜를 분명히 보인다(예: "내일 → 11월 3일(화)")                                                 |
| 앱의 내부 처리(정리 대기 표시 떼기 등) · 본문 밖 칸 고치기 | 기준 시각을 바꾸지 않는다                                                                                                                                                                    |
| 푼 날짜나 시각이 이미 지났다                               | 저장하지 않고 묻는다                                                                                                                                                                         |
| 고칠 대상이 그사이 바뀌었거나 지워졌다                     | 오래된 요청으로 덮지 않는다. 지금 값을 보이고 다시 묻는다                                                                                                                                    |
| 해석 응답을 받기 전에 시간 초과                            | 아이템 저장을 시작하지 않은 상태다. 문장을 보존하고 다시 시도할 수 있다                                                                                                                      |
| 저장 응답을 받지 못했다                                    | 성공·실패를 확정하지 않고 기존 저장 요청의 상태를 확인하거나 같은 요청을 재전송한다. 새 AI 요청으로 중복 생성하지 않는다. 묶음 저장의 재시도 식별·중복 방지는 F-43의 구현 전 확인에 포함한다 |
| 사용자가 정리 대기 아이템을 지웠다                         | 다시 시도하지 않는다                                                                                                                                                                         |

- **연결이 돌아왔다는 이유만으로 실행하지 않는다.** 다시 시도는 사용자가 누를 때 한다.
- 날짜 없는 아이템이라 만든 날의 보드에도 선다(F-26).
- 웹은 연결이 있으면 같은 방식으로 정리 대기에 저장한다. 연결이 없으면 쓰기를 막으므로(F-44) 문장을 입력 바에 남기고 다시 보내기를 띄운다. 그 문장은 탭을 닫으면 사라지므로 닫으려 하면 알린다.

### F-50. 대화 기록과 설정 패널

오른쪽 위 단추로 여는 패널이다. 보낸 문장과 그 결과를 날짜별로 모으고, 맨 아래에 알림 목록과 설정 입구가 있다.

**동작 흐름**

1. 사용자가 오른쪽 위 단추를 누른다.
2. 패널이 날짜별 묶음으로 보낸 문장 한 줄(넘치면 말줄임)과 결과 요약(일정 몇 · 할 일 몇 · 고침 몇 · 지움 몇 · 찾음 몇, 또는 정리 대기 · 답을 기다림)을 보인다.
3. 줄을 누르면 지금 화면 위에 그 대화와 결과 요약(F-48)을 다시 연다.
4. 맨 아래 "알림 목록"은 알림 목록(F-41)을, "설정"은 설정(F-46)을 연다. 새 알림이나 풀지 않은 충돌이 있으면 패널을 여는 단추에 표시한다(F-07).

**규칙**

- **그때의 결과와 지금 상태를 나눠 보인다.** 다시 연 결과 요약은 요청 당시 무엇을 했는지 보이고, 그 뒤 바뀌었거나 지워진 아이템에는 그 사실을 단다.
- 다시 연 결과의 되돌리기도 F-48의 되돌리기 규칙을 따른다. 그 뒤의 변경을 덮지 않는다.
- **대화 기록은 서버에 둔다.** 사람이 적은 글이라 암호화해 저장하고(4.4), 같은 계정이면 어느 기기에서든 같은 기록을 보고 이어 답한다.
- **사용자가 지울 때까지 둔다.** 패널에서 대화 하나를 지우거나 기록 전체를 지운다. 전체는 확인을 받는다. 지운 기록은 휴지통을 거치지 않는다. 그 대화로 저장한 아이템은 그대로 두고, 그 결과의 되돌리기만 사라진다. 탈퇴하면 계정과 함께 지운다(F-06).
- **받는 법:** 워크스페이스를 통째로 받을 때(F-02) 대화 기록은 넣지 않는다. 패널을 열면 최근 것부터 나눠 받는다. iOS는 최근 것을 기기 사본에 두어 먼저 그리고, 웹은 받은 것을 탭 메모리에만 둔다.

## 4.2 시간과 날짜

- 시각 있는 값은 아이템의 표준 시간대에서 정한 시각이고(F-12), 보는 기기의 표준 시간대로 보인다. 저장은 ISO 8601 UTC(Z) 한 형식으로 해 문자열 비교가 시각 비교와 같게 한다.
- **표준 시간대가 빈 시각은 떠 있는 시각이다.** 어느 표준 시간대에서 보든 같은 벽시계 시각에 선다. MVP에서는 앱이 시각 있는 아이템에 늘 표준 시간대를 넣고 떠 있는 시각을 고르는 화면은 두지 않는다(6장). ICS의 떠 있는 시각은 가져올 때 계정의 기본 표준 시간대를 넣는다.
- 종일 값과 날짜만 고른 마감은 날짜만 뜻하고 모든 시간대에서 같은 날에 선다. **끝은 마지막 날의 다음 날이다**(iCalendar와 같다). 오늘이 끝 날짜와 같거나 뒤면 지난 것이다. 회차 예외도 같은 기준이다.
- 날짜 경계는 0시이고, 오늘과 지난 날은 보는 기기의 날짜로 정한다.
- 시간표의 시간대는 날짜와 시간대 없는 시:분과 요일이다.

## 4.3 보안

- **세션:** 서버 세션(Spring Session + Redis). 인증 상태가 바뀔 때마다 세션 id를 새로 발급한다. 로그인 전 세션은 30분 무활동이면 끝난다.
- **도메인과 쿠키:** 웹앱은 app, 사이트와 문서는 www, API는 api 하위 도메인이고 같은 등록 도메인 아래에 둔다. 세션 쿠키는 API 호스트에만 Domain 속성 없이 발급하고 SameSite=Lax, 운영에서 Secure다. CORS는 app과 개발 주소만 허용한다. www에는 우리가 빌드한 정적 페이지만 싣고 외부 서비스의 스크립트를 싣지 않는다. 형제 하위 도메인끼리는 same-site라서 SameSite=Lax가 그 사이의 요청을 막지 않기 때문이다.
- **비밀번호:** 8자 이상, 흔하거나 유출된 목록은 거부, 64자 넘어도 받는다. Argon2id로 해시하고 매개변수는 OWASP 권고 이상(예: 19 MiB · 반복 2 · 병렬 1)이며, 올리면 다음 로그인 때 다시 해시한다.
- **계정 유무를 드러내지 않는다.** 가입 · 재설정 · 로그인 실패 · 코드 입력의 응답, 처리 경로, 응답 시간이 계정이 있든 없든 같다. 계정이 없어도 비밀번호 해시를 한 번 돌린다.
- **Apple 로그인:** 서버가 만든 nonce(웹은 state도)를 시작한 쪽에 묶어 한 번만 받는다. 이메일이 빈 토큰은 받지 않고, 이메일 확인 값은 문자열 "true"와 불리언 true만 참으로 본다.
- **권한:** 모든 접근에서 서버가 소유를 확인하고, DB 접근은 서비스 레이어로만 한다. 없는 대상과 권한 없는 대상은 같은 응답이다. 아이템 id는 비밀이 아니라 암호화하지 않는다.
- **입력 렌더:** 스크립트가 실행될 수 있는 마크업을 허용 목록 방식으로 걷는다.
- **로그에 남기지 않는 값:** 사용자가 적은 글, 비밀번호, 세션 id와 로그인 유지 값, 메일 코드와 "내가 아니다" 링크 값, 구글 · Apple 토큰, AI 입력과 결과, 캡처 이미지와 인식 결과. 아이템 id와 사용자 id는 된다.
- **운영자 접근:** 접속 기록을 위변조 못 하게 1년 이상 둔다. 사람 계정은 평소 KMS 복호화 권한이 없다.
- **AI 해석에 보내는 것:** 문장, 해당 요청의 기준 시각과 시간대(F-49의 재시도 기준 포함), 요청에 묶인 모듈 종류와 날짜나 주, 사용자가 고른 아이템과 기기가 고른 후보 아이템의 칸(이름 · 때 · 반복 · 알람 · 소속), 지침(F-46). 화면 전체, 워크스페이스 전체, 조회로 찾은 결과는 보내지 않는다. 무엇을 보내는지 첫 사용 동의에 적는다.

## 4.4 개인정보와 데이터 수명

- **사람이 적는 글은 서버가 암호화해 저장한다.** 아이템의 이름 · 본문 · 장소 · 태그, 가져온 ICS 값, 컬렉션 이름, 지침과 그 이력 · 충돌 기록 · 대화 기록이다. 사용자마다 데이터 키를 두고 KMS로 감싸 DB 밖에 둔다. 사용자 이름은 메일에 쓰여 평문이다.
- **서버는 그 글을 해석하지 않는다.** 그 값으로 거르기 · 정렬 · 검색 · 위키링크 읽기 · 비교를 하지 않고 기기가 한다. 서버가 키를 쥐므로 "운영자도 못 본다"고 안내하지 않는다.
- **웹은 사용자 데이터를 기기에 남기지 않는다.** localStorage · sessionStorage · IndexedDB · Cache Storage · OPFS · 쿠키에 두지 않고 API 응답은 no-store다. 남기는 것은 셋뿐이다: 아이디 저장, 기기 id 쿠키, 브라우저 알림. 웹의 자유 글 칸과 검색 칸은 브라우저 자동 완성 기록을 끈다.
- **iOS 기기 사본**은 받아 둔 워크스페이스 · 내려 둔 입력 화면(해당 기능을 제공하는 경우) · 검색어 · 알림 목록 보관분 · 최근 대화 기록이다. 사용자별로 두고 iCloud 백업과 기기 이전에서 뺀다. 로그인 유지 값은 이 기기에서만 읽히는 Keychain에 둔다.
- **보관 기간:** 휴지통 30일 뒤 물리 삭제(이력 · 충돌 기록 포함), 탈퇴 30일 뒤 계정 · 그 계정만 속한 컬렉션 · 데이터 키 삭제. 대화 기록은 사용자가 지울 때까지 둔다(F-50). 키 저장소 백업은 7일, DB 백업은 35일까지만 두고, 복원하면 그 뒤의 삭제를 다시 적용한다.
- **서버는 사용자 글을 해석하지 않는다는 원칙의 예외:** 사용자가 동의한 AI 해석 요청은 서버를 거쳐 외부 AI 서비스로 간다. 캡처의 서버 인식(F-34)도 동의를 받은 예외다. AI 해석 요청은 로그에 남기지 않는다. 보낸 문장과 결과는 사용자의 대화 기록(F-50)으로, 처리하지 못한 문장은 정리 대기 아이템(F-49)으로만 남는다.

## 4.6 접근성

- 웹은 키보드만으로 홈과 모든 모듈에 닿고, 캘린더 격자에서 이동 · 생성 · 조회가 된다. 단축키는 한글 입력 중에도 동작하도록 물리 키 코드(event.code)로 판정한다.
- 포커스와 선택은 늘 외곽선으로 보인다. 라이트 · 다크 모두 WCAG 2.1 AA 대비(본문 4.5:1, 큰 글자와 UI 3:1)를 지킨다.
- 브라우저 줌 200% · OS 배율 150%까지 글자 잘림 · 겹침 · 가로 스크롤 · 조작 요소 이탈이 없다. 월력 · 주간 격자 · 시간표 모듈은 예외이고, 웹은 일정 나열 모드로, iPhone은 일 상세로 같은 정보를 읽게 한다.
- 일정 칩은 24px보다 작을 수 있다. 상세가 모든 정보를 보이고, 짧은 블록에는 접근성 이름을 붙인다.
- 상태에 따라 모양이 바뀌는 단추는 접근성 이름도 함께 바꾼다. 입력 바의 단추는 입력이 비면 「직접 입력」, 적으면 「보내기」다(F-08).

## 4.7 운영

- **메일:** 서버가 트랜잭션 메일 서비스로 SMTP 발송하고 설정만 바꿔 제공자를 교체한다. 발신은 서비스 도메인의 no-reply이고 SPF · DKIM · DMARC를 건다. 서비스 전체 시간당 발송 상한을 두고, 반송률이 경고 수준이면 운영자에게 알린다.
- **입력 화면 구성**은 서버 배포와 따로 도는 시드 작업이 DB에 넣는다. 여러 번 돌려도 결과가 같고 사용자의 데이터를 건드리지 않는다.
- 특정 사용자군의 말은 필드 이름과 미리 넣는 데이터에 넣지 않는다.

**아직 정하지 않았다:** 서비스 도메인 이름(세 하위 도메인 · 구글 로그인 주소 · 메일 도메인 · Apple 로그인 주소 · CORS가 쓴다). 클로즈 베타 지표(30일 리텐션 · 활성 사용자 비율 · 1인당 만들기 수)를 무엇을 어디에 얼마 동안 남길지.

# 5. 시연 시나리오

발표 때는 아래 다섯 단계로 라이브 데모를 진행한다. 날짜 예시는 2026년 11월 4일(수)을 오늘로 둔 시연 환경 기준이며, 실제 시연에서는 같은 관계의 날짜로 맞춘다.

1. **시작: 설정 없이 들어온다**
   - 가입하면 홈이 열린다. 오늘 날짜와 비어 있는 오늘, 아래에 AI 입력 바가 있다.
   - 입력 바를 누르자 예시 문장이 보인다. 하나를 눌러 입력 바에 채워 보고 지운다.
2. **시간표: 캡처 한 장으로 한 주를 채운다**
   - 시간표 모듈의 빈 상태에서 불러오기를 누르면 만드는 페이지가 열린다. 넣을 컬렉션과 기간을 정하고 쓰던 시간표 앱의 캡처를 올린다.
   - 보정 격자에서 틀린 장소 하나를 고치고 만들기를 확정한다.
   - 시간표 모듈에 한 주 격자가 서고, 캘린더 월력에는 시작일부터 회차가 날짜마다 선다.
3. **하루 중: 지금 화면에서 문장으로 정리한다**
   - 시간표 모듈에서 오늘 저녁 영어 수업 블록을 누르자 회차 상세가 열리고, 입력 바 위에 "선택한 항목: 영어 수업 · 11월 4일(수)"이 보인다. "이번 주만 오후 7시로 옮겨 줘"를 보낸다.
   - 상세의 시각이 오후 7시로 바뀌어 "고침"으로 강조되고, 결과 요약에 "영어 수업 · 이번 주 수요일만 · 오후 6시 → 오후 7시"가 뜬다. 상세를 닫으면 시간표 모듈에서 블록이 오후 7시 자리에 "이번 주만" 표시와 함께 서 있다. 화면은 시간표 모듈 그대로다.
   - 입력 바 위에 "방금 고친 항목: 영어 수업 · 11월 4일(수)"이 이어져 있다. "오후 8시로 바꿔 줘"를 보내자 같은 회차가 오후 8시로 바뀐다. 결과 요약의 되돌리기를 눌러 오후 7시로 돌아온 것을 본다.
   - 캘린더 모듈로 가서 11월 4일(수) 일 상세에서 "오후 2시에 팀 회의 잡아 주고, 같은 날 보고서 보내기 할 일도 넣어 줘"를 보낸다. 두 결과가 일 상세에 강조되고, 결과 요약 한 목록에 두 줄로 선다.
   - 홈으로 가면 오늘 줄에 바뀐 수업과 새 팀 회의가 보인다. 할 일 줄은 그 자리에서 체크할 수 있다.
4. **다음 날: 틀어진 계획을 앱이 제안한다**
   - 아침에 "오늘 뭐 있어?"를 보내면 오늘의 일정과 할 일이 목록으로 뜬다.
   - 어제 체크하지 않은 "보고서 보내기"가 홈의 밀린 할 일에 "오늘 14:00" 제안과 함께 서 있다.
   - 제안을 누르자 오늘 오후로 옮겨진다. 누르기 전에는 앱이 아무것도 옮기지 않았다.
   - 반복 할 일의 회차는 미루면서 "다음 회차로 넘기기"를 고르고, 그 회차는 취소선으로 남는다.
5. **일정이 바뀌고, 두 기기가 부딪친다**
   - 이번 주만 시간이 바뀐 시간표 회차를 캘린더에서 끌어 옮기면 그 회차만 바뀐다.
   - 다음 주부터 시간이 아예 바뀐다. 시간표 모듈의 회차 상세에서 ⋯ 메뉴의 반복 고치기로 마스터 상세를 열고 적용 시작일을 다음 주 월요일로 바꿔 시각을 고치면 이번 주와 지난 주는 그대로다.
   - iPhone을 비행기 모드로 두고 한 일정의 장소를 고치고, 웹에서 같은 장소를 다르게 고친다. 연결을 돌리면 알림 목록에 충돌이 뜨고, 눌러 두 값 가운데 하나를 고르면 두 기기 모두 정리된다.

# 6. MVP 밖

- 간트 모듈과 칸반 모듈(시장 반응을 본 뒤 다시 정한다)
- iPhone 캘린더의 주간 보기(웹의 주간 보기는 MVP에 있다, F-29)
- 시간표의 격주 · 월 1회 같은 매주 아닌 반복
- URL로 외부 캘린더를 구독해 동기화하기
- 아이템 순서를 끌어서 직접 정하기
- 슬래시 명령 확장(이미지 · 표 · 콜아웃 · 임베드 · 수식)
- 일정 · 할 일의 이름 안에서 쓰는 위키링크
- 서버 풀텍스트 검색과 태그 동의어
- 노트 실시간 공동 편집
- 사용자 정의 위젯과 위젯 크기별 표시
- 사용자가 입력 화면을 직접 조립하고 붙이기, 그 목록 화면, 직접 입력 메뉴에서 새 입력 화면 만들기
- 입력 화면에서 칸을 숨기거나 기본값을 주는 구성
- 이미 있는 아이템을 고치는 입력 화면, 여러 아이템을 한 번에 고치는 입력 화면
- 아이템 생성 밖의 앱 명령을 입력 화면 구성으로 다루기
- 사용자가 만든 입력 화면을 사고파는 마켓
- 한 계정이 워크스페이스를 여럿 갖고 주소로 나누기. MVP는 계정마다 워크스페이스 하나이고, 데이터는 지금부터 워크스페이스 단위로 나눠 둔다
- 카카오 로그인
- 로그인 방법 목록과 제공자 끊기 화면
- 컬렉션 공유와 공유 링크, 협업
- 생성 · 수정까지 담는 전역 활동 기록과 복원
- 서버가 보내는 푸시 · 이메일 · 웹훅 알림
- 삭제 확인 창을 끄는 설정
- 휴지통 비우기와 하나를 바로 지우기
- AI 도구가 아이템을 조회 · 생성하는 MCP 서버
- 모아보기의 출처 연결 펼침과 그룹
- 모아보기의 거르기, 여러 아이템의 색 · 태그 · 상태 · 기간을 한 번에 고치는 일괄 편집
- 테마 추가(Modern · Retro · Mono)
- 요금제별 AI 사용 한도
- Android 네이티브 앱
- iOS 앱의 외부 URL 기반 딥링크와 앱 URL 스킴. 위젯·기기 알림의 특정 화면 진입은 F-36 「위젯 둘」에서 별도로 범위를 정한다
