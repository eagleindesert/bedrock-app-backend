# 1. 나누는 원칙

1. **BE는 저장 · 검증 · 권한 · 합치기 · 묶음 저장 · 암호화 · 메일 · AI 중계를 맡는다.** 사용자가 적은 글은 해석하지 않는다(명세 4.4).
2. **FE는 받아 둔 워크스페이스로 계산한다.** 검색 · 거르기 · 정렬 · 회차 계산 · 재조정 제안 · 조회 실행 · 고칠 대상 후보 고르기 · 위키링크 읽기 · 같은 값 가리기 · ICS 읽고 쓰기가 FE의 일이다.
3. **같은 규칙을 iOS와 웹이 따로 만든다.** 회차 계산 · 합치기의 기기 쪽 · 거르기와 정렬 · 빈 시간 계산 · 조회 실행 · 위키링크 읽기 · ICS가 그렇다. 두 앱이 같은 답을 내도록 공통 테스트 사례를 둔다. 사례는 JSON 한 벌(입력 워크스페이스 · 질문 · 기대 답)로 두고 iOS와 웹이 같이 돌리며, 관리는 BE가 한다(2026-11-11 정함, iOS 쪽은 iOS 아키텍처).
4. **오프라인 쓰기는 iOS만 한다.** 기기 사본과 보내지 않은 쓰기 줄은 iOS가 맡고, 웹은 연결이 있을 때만 쓴다.
5. **마지막 검증은 BE가 한다.** FE가 미리 검사한 것(필수 칸 · 겹침 · 값 범위)도 BE가 다시 본다. 받아들이지 않은 쓰기는 FE가 되돌리고 알린다.

# 4. 기능 구현 추천 순서

1. **BE 확인부터.** 명세 F-43의 "구현 전에 확인한다"(한 묶음 저장 · 재전송 중복 막기)가 되는지 먼저 본다. 안 되면 F-43을 다시 정해야 해서 AI 일정이 갈린다.
2. **API 명세:** BE가 낸다. FE가 기다리지 않도록 동기화(받기 · 쓰기 · 응답 꼴)와 인증을 먼저 내고, 동기화는 iOS가 보고 확정한다. AI는 F-43 확인 뒤에 낸다.
3. **기반:** 기반이 붙은 일곱 기능(F-02 · F-04 · F-09 · F-12 · F-23 · F-43 · F-44)과 나머지 계정 기능(F-01 · F-03 · F-05 · F-06). iOS는 셸(F-07)을 함께 시작한다.
4. **코어:** F-08 · F-11 · F-13 ~ F-22 · F-24 ~ F-28 · F-37 ~ F-40 · F-45 · F-46 · F-51 · F-52.
5. **AI:** F-43의 FE 몫 · F-47 ~ F-50.
6. **나머지:** F-29 · F-30 ~ F-34 · F-41 · F-42, 그리고 MVP 여부가 미정인 F-10 · F-35 · F-36.

# 5. 정할 것

- **웹 착수 시점:** 명세는 iOS를 먼저 완성한다고 한다. 웹 모듈 오가기와 입력 바 자리도 아직 정하지 않았다(명세 4.1).
- **"내가 아니다" 확인 화면:** 로그인 없이 여는 웹 화면이다. 웹이 iOS보다 늦게 시작하면 BE가 단순한 페이지로 낼지 정한다.
- **외부 AI와 캡처 인식 엔진:** 무엇을 쓸지와 한도 값은 BE가 정한다.
- **옛 API 문서:** 개발용 API Schema (REST · v2.0)는 옛 기획 기준이다. 다시 쓸 부분이 있는지 BE가 본다.
